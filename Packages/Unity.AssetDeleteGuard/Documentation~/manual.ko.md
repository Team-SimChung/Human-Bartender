# Asset Delete Guard 한국어 안내

Project 창에서 삭제하려는 파일 또는 폴더를 선택하고 **Assets > Asset Delete Guard > Review References**를 실행하면 참조 출처를 볼 수 있습니다. 실제 삭제는 **Review and Delete**에서 진행합니다. 대화형 Editor의 기본 Delete도 기본적으로 연동됩니다. 파일 탐색기와 배치 모드 삭제는 연동 범위 밖입니다.

## 검사 결과 읽기

- 상단 카드에는 삭제 대상 에셋, 직접 참조 출처, 간접 영향 수를 표시합니다. 카드를 누르면 해당 탭으로 이동합니다.
- **삭제 파일**에는 폴더 내부의 숨김 파일, Unity 미등록 파일, `.meta`까지 표시합니다.
- **직접 참조**는 삭제 후 남게 되는 에셋·열린 씬·설정의 직접 참조입니다. 공급자와 출처 단위로 묶으며 행을 선택하면 아래에 대상 파일과 속성을 표시합니다. 함께 삭제되는 파일 사이의 참조는 제외합니다.
- **간접 영향**은 직접 참조자를 다시 참조하는 파일입니다. 실행 시 오류가 확정됐다는 뜻은 아닙니다.
- **위치 보기**로 출처 파일/열린 객체를 선택하고 **보고서 저장**으로 로컬 JSON을 내보낼 수 있습니다.
- **검사 범위**에는 오류와 한계를 모아서 표시합니다. 검사 상태와 확인·삭제 버튼은 창 하단에 고정됩니다.

## 기본 Delete 연동

창 오른쪽 위의 **기본 Delete 연동** 또는 **Tools > Asset Delete Guard > Guard Native Delete**에서 켜고 끕니다. 두 UI가 같은 설정을 사용하며, 사용자·프로젝트별 로컬 설정입니다. Assets에 설치한 플러그인을 제거할 때는 먼저 연동을 끄세요.

기본 Delete를 누르면 Unity의 확인창이 먼저 나오고, 파일 삭제 단계에서 플러그인이 삭제를 차단합니다. Unity가 **Cannot Delete**를 표시할 수 있으며, 이 안내를 닫으면 참조 검토 창이 열립니다. 검토 창을 닫거나 취소하면 파일은 그대로 남습니다. 원래 명령을 자동으로 재실행하지 않습니다.

콜백에는 파일 경로만 있으므로 다른 도구의 대화형 AssetDatabase 삭제도 차단 대상입니다. 다음 에디터 업데이트까지 차단된 경로를 모아서 보여주지만 하나의 원래 작업/트랜잭션으로 간주하지 않습니다. 배치 모드, 파일 탐색기, Packages 경로, 메타데이터 단독 삭제는 제외합니다. 서브에셋에서 시작했는지는 알 수 없어 Unity가 요청한 부모 파일 경로를 보여줍니다.

**Material Variant는 전용 Review and Delete 메뉴를 사용하세요.** Unity가 삭제 콜백 전에 자식 Material의 부모를 변경할 수 있어 기본 Delete 연동이 이 선행 변경까지 되돌릴 수는 없습니다. 다른 도구가 삭제 전에 수행한 작업도 마찬가지입니다. Unity는 다른 삭제 콜백도 호출하므로 그 콜백이 직접 파일을 변경하는 경우 역시 차단·원복을 보장하지 않습니다. 전용 메뉴에서는 발견된 Material Variant 부모의 삭제를 사전에 차단합니다.

승인된 삭제도 기존 전체 재검사·삭제 실행기를 사용합니다. 실행 중에는 검토한 디스크 항목만 통과시키며 예외가 나도 승인은 해제됩니다. 대기 요청은 코드 리로드·Play Mode 전환·Editor 종료·연동 끄기에서 폐기합니다. 검토 창 닫기·리로드·Play Mode 전환 시 검사와 승인을 폐기하며, 승인이나 대기열을 저장하지 않습니다.

`Ready`는 표시된 검사 범위의 처리가 끝났다는 뜻입니다. 참조가 0개여도 동적 로딩까지 안전하다는 보장은 아닙니다. `Partial` 또는 `Cancelled` 결과로는 삭제할 수 없습니다. 자세한 오류 메시지는 현재 영어로 표시됩니다.

## 삭제와 복원

참조 및 검사 한계를 확인하고 체크한 다음 **재검사 후 삭제**를 누릅니다. 확인창 이후 전체를 다시 검사하며, 파일 내용·GUID·폴더 구성·참조 결과 등이 바뀌면 삭제하지 않고 새로운 보고서를 표시합니다. 사용한 승인은 재사용하지 않습니다.

미저장 변경이 있는 삭제 대상, 읽기 전용 파일, 누락된 메타 파일, 링크/정션 경로, 서브에셋 선택, 발견된 Material Variant 부모, 검사 실패는 삭제를 차단합니다. 씬의 누락된 스크립트도 검사 실패 원인이 됩니다. 검사 취소, 창 닫기, 스크립트 리로드 후에는 다시 검사해야 합니다.

Unity 휴지통 API를 호출하지만 운영체제·VCS에 따라 휴지통 보관을 보장할 수 없습니다. Unity Undo로 복원할 수 없습니다. 일부만 삭제될 수 있으므로 파일별 결과를 확인하세요. 자동 재시도·영구 삭제 전환은 없습니다. 복원할 때는 파일과 **원래 `.meta`를 함께** 복원해야 GUID 참조가 유지됩니다.

## 범용 패키지와 지원 범위

게임 코드, 특정 씬 이름, URP/HDRP, Addressables 등 별도 프레임워크에 의존하지 않는 Editor 전용 패키지입니다. 로컬 UPM 또는 `.unitypackage` 중 하나로 설치하며 두 방식을 중복 설치하지 마세요.

저장된 파일 의존성, 열린 씬/Prefab Stage의 직렬화 참조, 비활성 객체, 씬 설정, 임시 Material/ScriptableObject 내부 참조, 빌드 씬·프로필과 Preloaded Assets 등을 검사합니다. 문자열 경로/GUID, 코드에서 로드하는 리소스, Addressables 등록과 AssetReference 문자열, 기타 ProjectSettings 전체는 현재 검사하지 않습니다. 참조 자동 교체나 Unreal Redirector와 같은 중간 에셋도 만들지 않습니다.

구현상 최소 목표는 Unity 2019.4 LTS이며 실제 자동 테스트를 실행한 환경은 **Windows / Unity 6000.3.14f1**입니다. 이전 버전과 macOS/Linux는 별도 검증이 필요합니다. 아직 모든 Unity 버전 호환이나 마켓 심사 통과를 보장하는 출시 버전이 아닙니다.

최초 검사와 삭제 직전 검사는 전체 스캔입니다. 대규모 프로젝트에서는 재검사 중 Editor가 일시 정지할 수 있습니다. 상세 범위와 복구 설명은 `manual.md`, 판매 준비 항목은 소스 체크아웃의 `Tools~/marketplace.md`에 정리되어 있습니다.
