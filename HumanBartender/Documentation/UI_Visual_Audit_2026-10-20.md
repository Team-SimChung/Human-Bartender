# UI 리소스·배치·연출 종합 검토

검토일: 2026-10-20

후속 적용 기록: [UI_Visual_Update_2026-10-20.md](UI_Visual_Update_2026-10-20.md). 아래는 구현 전 검토 내용이다.

## 결론과 전제

웹 데모를 시각 기준으로 삼되, 팀원들이 Unity 환경에 맞게 재구성한 기존 화면·입력·진행 구조를 보존하는 작업이다. 웹 파일과 Unity 파일이 같아야 한다는 전제로 판단하지 않았다.

현재는 **새 원본은 들어왔지만 이전 이미지가 연결된 화면**, **새 리소스로 일부 재구성한 화면**, **이미지 외에 배치나 동적 효과를 추가해야 하는 화면**이 섞여 있다. 폴더 이름에 Legacy가 있다는 이유만으로 일괄 교체하면 안 된다. 실제로 새 폴더와 Legacy 폴더의 PNG가 동일한 사례도 있다.

이번에는 폴더·커밋·이미지·참조·표시 코드와 로컬 웹 화면을 조사했다. 검토 문서만 추가했으며 UI 구현은 변경하지 않았다. 앞선 대화에서 수정한 캐릭터·말풍선 작업은 현재 미커밋 상태 그대로 포함해 비교했다.

기준 저장소는 Unity `79ff6201`, 웹 `7e58c0d`다. 로컬 웹 HEAD는 원격 저장소 HEAD와 일치했다. GitHub Pages 배포 캐시까지 동일하다고 검증한 것은 아니다.

## 대화창 크기와 글자 기준

첨부 첫 이미지처럼 **짧은 한 줄에서도 이름과 본문이 들어갈 박스 면적을 확보**해야 한다. 글자에 맞춰 아주 좁은 박스부터 만들고 패딩만 더하는 방식으로는 같은 인상이 나오지 않는다.

웹의 바 화면은 1280×720 기준이고 현재 Unity 대화 Canvas는 960×540 기준이다. 두 값을 그대로 복사하지 않고 0.75 비율로 환산한 뒤 16:9 실제 화면에서 조정한다.

| 항목 | 현재 Unity 프리팹 | 웹 기준 | Unity 960×540 환산 제안 |
| --- | --- | --- | --- |
| 최소 너비 | 50 | 269 px | 약 202 |
| 최소 높이 | 65 | 108 px | 81 |
| 최대 너비 | 560 | 618.7 px | 약 464 |
| 둘이 앉은 대화의 최대 너비 | 별도 레인 기준 확인 필요 | 520 px | 390 |
| 좌우 여백 | 최근 수정 24/24 | 38/38 px | 28.5/28.5 |
| 박스 상하 여백 | 본문 top 30, bottom 20. 이름이 별도 배치됨 | 상 22, 하 24 px | 상 16.5, 하 18 + 이름 행 |
| 화자 | 15, 별도 NameText | 20 px / 줄높이 24 px, 본문과 간격 10 px | 글자 15 / 줄높이 18 / 간격 7.5 |
| 본문 | 15, NeoDunggeunmo SDF, lineSpacing 45 | 18 px / line-height 1.45 | 글자 약 13.5 / 줄높이 약 19.6 |

환산 수치는 적용 목표 초안이다. TMP 행간과 CSS line-height는 단위와 폰트 메트릭이 다르므로 숫자만 복사하지 않는다. 본문 top inset은 박스 상단 여백에 이름 행·이름과 본문의 간격을 더해서 계산한다. 이름을 프레임 모서리에 얹는 기존 배치와 분리한다.

웹의 현재 대화 폰트는 PFStardust 계열이다. Unity에도 Regular/Bold PFStardust SDF와 Medium/Bold Paperlogy SDF가 이미 있다. NeoDunggeunmo를 유지할지 같은 계열로 맞출지에 따라 글자 폭과 줄바꿈이 바뀌므로 폰트 결정 후 박스 크기를 확정한다.

줄바꿈은 강제 개행 보존 → 실제 본문 너비 → 띄어쓰기 단위의 자동 줄바꿈 순서로 처리한다. 다음 입력 표시는 별도 여백을 확보한다. 고객·플레이어·일반 손님 대화의 공통 스킨과 화면별 배율을 함께 확인한다.

원본 `dialogue_screen_customer.png`와 `title_screen.png`는 완성 배치를 보여 주는 합성 참고 이미지다. 화면 전체를 그대로 버튼 배경으로 넣거나 텍스트가 구워진 참고 이미지를 인터랙티브 UI로 사용하지 않는다. GRD_textbox 조각은 알파·스프라이트 영역·꼬리를 확인한 뒤 조립한다.

## 메인 메뉴와 설정 적용 범위

메인 메뉴는 배경, 로고, 점무늬/장식, 버튼의 기본/강조 이미지, 실제 TMP 글자로 나눈다. 웹과 같은 구도·크기·상태 색을 맞추되 Unity의 새 게임 시작과 저장 슬롯 불러오기 흐름을 연결한다. 웹의 이어하기 비활성 상태를 Unity에 복사하지 않는다.

웹 설정은 하나의 완성 PNG가 아니다. 창·구분선·슬라이더·토글·문구는 CSS와 HTML로 조립하고, 서비스 메뉴 아이콘·프로필 닫기 아이콘·선택 배경 같은 일부 그림만 재사용한다. 따라서 설정은 Unity 레이아웃과 상태별 스타일을 재구성해야 한다.

| 설정 요소 | 처리 방향 |
| --- | --- |
| 외형 | 웹의 1000×540 창 비율, 헤더·좌측 218px 탭·본문·하단 버튼을 기준으로 uGUI 배치 |
| 기존 기능 | 전체화면/창 크기, BGM/SE 저장과 적용 유지 |
| 웹의 추가 항목 | 거리 환경음, 대사 출력음/미리 듣기, BGM/제조음 토글, 출력 속도·언어·포커스 일시정지는 대응 기능 존재 여부부터 확인 |
| 조작 안내 | Unity 실제 키·게임패드·마우스 입력에 맞는 안내 문구 사용 |
| 공통 사용 | 타이틀·바·외부에서 같은 뷰 사용. 닫기/Esc/포커스와 입력 차단 확인 |

현재 AudioVolumeSettings에는 BGM/SE 두 사용자 음량만 공개되어 있다. 웹 항목처럼 보이게 버튼만 만들고 기능이 연결됐다고 처리하지 않는다. 추가 설정 기능은 이번 리소스 갱신과 구분해 구현 범위를 기록한다.

## 글리치는 세 가지 시각 상태로 구분

| 효과 | 웹에서 확인한 기준 | Unity 구현 방향 |
| --- | --- | --- |
| 로고 자체 | 약 2.86초 주기. 로고를 가로 띠로 나눠 순간적으로 좌우 변위 후 깨끗한 원본으로 복원 | 로고 전용 Image 재질/메시 처리. 배경·버튼은 같이 흔들지 않음 |
| 타이틀 메뉴 글자 | hover/키보드 focus 진입 시 약 0.3초 한 번. 작은 좌우 이동과 청록/분홍 조각 | 메뉴 상태에 연결한 TMP 글자 효과. 포커스 변경·비활성화 때 복원 |
| 바 대화 선택지 글자 | 누르고 있는 동안 0.3초 애니메이션 반복. 놓기·취소·분기 전환 때 즉시 제거 | ChoiceHoldButton의 홀드 상태와 글자 효과 연결. 배경과 진행바는 별도 유지 |

Unity의 LogoFade는 0일차 엘리베이터 로고의 페이드·선택적 이동이다. 10월 20일 수정도 OutSide 씬과 Canvas_Logo에 한정되며 메인 메뉴의 반복 글리치가 구현됐다는 뜻은 아니다.

Legacy에 UI_GlitchPanel 셰이더/시험 머티리얼은 있으나, 위 세 상태의 연출과 연결이 같다고 확인되지 않았다. 이름이 비슷하다는 이유로 그대로 붙이지 않는다. TMP 글자 효과는 기존 대사 shake/wave와도 수명과 대상이 다르므로 별도 상태로 관리한다.

웹의 선택 확정은 0.5초, 현재 Unity ChoicePanel은 1초다. 팀이 조정한 입력 규칙일 수 있으므로 **시각 갱신 과정에서 자동으로 0.5초로 바꾸지 않는다.** 누르는 동안 글리치를 보이게 하는 것과 확정 시간을 바꾸는 것을 분리한다.

## 권장 적용 순서

1. **기준표 고정:** 각 화면에서 유지할 Unity 동작, 사용할 원본, 현재 GUID/fileID, 목표 배치와 폰트, 상태별 이미지·효과를 기록한다.
2. **대화창 한 화면 먼저:** 첨부 첫 이미지 기준으로 이름 행·최소 크기·폰트·행간·꼬리·다음 표시를 맞춘다. 짧은 한 줄/긴 대사/두 손님/플레이어 대사를 같은 해상도에서 비교한다.
3. **바 선택지:** 새 A/B 연결과 기존 진행바의 중복 여부를 확인하고, Unity 1초 홀드에 글자 글리치만 연결한다. 외부 선택지 조각 UI는 별도 경로로 보존한다.
4. **메인 메뉴:** 새 타이틀 구도와 네 메뉴, 기존 저장/진행 기능을 연결한 뒤 로고·메뉴 글리치를 각각 적용한다.
5. **공용 설정:** 3탭 외형을 먼저 완성하고 기존 화면·음량 기능을 연결한다. 새 기능은 지원 여부를 명시하며 별도로 추가한다.
