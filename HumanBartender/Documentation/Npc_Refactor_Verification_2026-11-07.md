# NPC 구조 리팩토링 및 검증 기록

2026-11-07, Unity 6000.3.14f1의 현재 프로젝트에서 검사했다.

## 변경 내용

- Inspector: 사용자 요청으로 이번 시각 변경을 원복했다. 새 루트 편집기·공통 배치 도구를 제거하고 기존 동작 목록 Drawer를 복원한다. 기존 필드 표시와 한 줄 배치를 사용하며, 씬에 저장된 값은 변경하지 않는다. 아래 넓은 창·좁은 창 화면 확인은 원복 전 시각 변경의 이력이다.
- 실행 책임: `NpcInteraction`은 설정·등장·대화 세션을 맡고, 일반 C# 클래스 `NpcSequenceExecutor`는 동작 실행·좌표 계산·화면 복구, `NpcSequenceValidator`는 연결·수치 검사를 맡는다. 두 보조 클래스는 씬에 추가할 컴포넌트가 아니다.
- 중복 제거: 계약 연출 기본값과 에디터의 연출 목록 읽기·쓰기를 공통화했다. 기존 설정 도구의 긴 람다는 이름 있는 메서드로 분리했다.
- 코드 스타일: 관련 연결 계층의 생략된 접근자를 명시하고 변경한 설명 주석·Header를 한국어로 정리했다. 설정 데이터의 기존 공개 필드는 호환성을 위해 유지했다.
- Unity API: 구형 Sprite 슬라이스 접근을 Sprite 데이터 제공자 API로 교체했다. 기존 Sprite 식별자와 이름 연결을 유지한다.

## 유지한 데이터와 동작

직렬화 필드명·자료형·enum 값·기존 스크립트 GUID를 유지했다. `NpcActor`, `NpcMovement2D`, `NpcSceneStaging`의 실제 동작 코드는 변경하지 않았다. 대사·선택지·CSV 명령·결제·완료 플래그와 저장 형식도 유지한다.

수리공은 Exit Point 없이 명령 당시 위치에 상대 월드 X/Y를 더한다. 현재 작성값은 X=0.525, Y=0, 페이드 전 이동 1.1초, 퇴장 페이드 0.5초다. 화면 암전 0.35초 → 대기 1.35초 → 복귀 0.45초는 별도 동작으로 유지했다.

작업 시작 때 열려 있던 씬 편집을 백업·저장한 기준과 비교했다. CSV 48개, 씬 6개, 프리팹 53개, Animation 189개, Animator Controller 42개, 기존 meta 3,189개 및 Assets 내 문서 9개, 합계 3,536개 파일이 동일하다. 새 헬퍼 스크립트의 meta는 추가되지만 기존 참조는 바뀌지 않았다. 에디터 설정 도구를 실제 Home·OutSide에 재적용하거나 실제 그림 리소스를 재가져오지 않았다.

## 단계별 검사

| 단계 | 결과 |
|---|---|
| 기존 실행 코드 기준 검사 | 95개 중 94개 통과. 제자리 이동 중간 시점을 프레임 시간으로 추정하던 검사 1건을 보완 |
| 보완한 제자리 이동 검사, 기존 실행 코드 | 1개 통과 |
| Inspector 실제 화면 확인 — 이후 원복 | 변경 당시 넓은 창·좁은 창에서 확인했으나 사용자 요청으로 해당 시각 변경은 철회 |
| 실행 책임 분리 후 기존 회귀 검사 | 95개 중 94개 통과. 이미 완료된 짧은 페이드를 취소하던 검사 1건 확인 |
| 에디터 코드 적용 및 취소 검사 재검사 | 4개 모두 통과: 취소 검사 1개 + 새 에디터 검사 3개 |
| 리팩토링 검사 결과 — Inspector 원복 전, 재검사 반영·중복 제외 | **98개 통과, 미해결 실패 0개** |

Inspector 원복 전에는 임시 실행 도구를 제거한 뒤 최종 컴파일과 어셈블리 재로드가 성공했다. 이후 사용자 요청으로 Inspector 시각 변경만 되돌리고, 실행 책임 분리·에디터 도구·테스트 보완은 유지했다. 위 검사 수치는 원복 이후 새로 실행한 결과가 아니다.

검사는 수리공의 돈·부품 전달/부족/미결제 대기/재방문, 불량배 접근·타격·퇴장, 계약의 두 배우 실행 순서, 경비원 수동 대화, Home·OutSide 등장 조건, 입양 씬 전환, CSV 호출·효과 적용 순서, 취소·화면·카메라·루나 복구, 자동/수동 시작 범위를 포함한다.

새 에디터 검사는 다음을 확인한다.

1. 작성한 모든 동작 설정과 NPC·대상 참조의 읽기·쓰기 및 동작 교체 시 이전 필드 값 제거.
2. 계약 설정 재적용 시 사용자 연출 ID·조건·추가 목록 보존과 현재 카메라 동작 유지.
3. 복사한 텍스처를 두 번 재가져와도 Sprite의 GUID/local ID·영역·피벗·PPU가 유지됨. 검사 복사본은 정리됨.

두 타이밍 검사는 동작을 통과시키기 위해 런타임을 바꾸지 않았다. 제자리 이동은 검사 중 잠시 시간을 멈춰 조기 완료 여부를 확인한 뒤 실제 소요 시간을 검증한다. 부분 페이드 취소 검사는 해당 구간의 최대 프레임 시간을 제한하고 실행 중·미완료·부분 투명 상태를 확인한 후 취소한다. 두 검사 모두 `finally`에서 시간 설정을 복구한다.

## Inspector 원복 후 확인 — 후속 내부 정리 전 기록

사용자 요청으로 새 Inspector 표시만 철회했다. `NpcSequenceDrawer.cs`는 작업 전 파일과 해시가 같고, 추가한 `NpcInteractionEditor`·`NpcInspectorLayout`과 해당 meta를 제거했다. 나머지 변경 소스 16개 및 기존 데이터·참조 파일 3,536개는 원복 직전/보존 기준과 동일하다. 컴파일·어셈블리 재로드가 성공했고 실제 수리공 Inspector에서 기존 표시를 확인했다. 런타임 검사는 다시 실행하지 않았다. 근거는 `Logs/NpcInspectorRollback/verification.json`과 같은 폴더의 `compile.log`에 있다.

## Inspector 외형을 유지한 후속 내부 정리

사용자 승인에 따라 `NpcSequenceDrawer` 내부 세 항목을 정리했다. 루트 Inspector와 단일 선택의 기존 라벨·항목 순서·툴팁·행 배치는 유지한다.

- 동작 제목은 기존 `NpcActionKind`의 Inspector 표시 이름에서 읽어 중복 정의를 제거했다.
- CSV 명령 메뉴는 기존 16개 이름·순서를 유지하면서 명시적인 enum 값으로 연결한다. 사용자가 값을 변경했을 때만 기록한다.
- 다중 선택의 혼합값을 보호한다. 서로 다른 실행 방식·동작 종류에서는 공통 설정만 표시하고, 그리기가 끝난 뒤 들여쓰기·혼합 표시 상태를 복원한다.

이번 검사는 **12개 모두 통과**했다. 새 GUI 검사 4개가 기존 동작 제목 25개·명령 메뉴 16개·대표 동작의 높이를 확인하고, 실제 에디터 창에서 다중 선택을 반복해서 그려도 각 대상의 설정이 바뀌지 않는지 검사한다. 기존 검사 8개는 CSV 대사·연출·효과 적용 순서, 취소 후 재시도, 수리공의 화자 연결·상대 이동·화면 암전과 퇴장 시간 분리, 사용자 설정 보존, 기존 저장 플래그 복원 경로를 확인한다. 전체 이전 98개 검사를 다시 실행한 결과는 아니다.

첫 GUI 검사에서 발견한 종료 처리 후 혼합 표시 상태 복원 순서를 보완했다. 다중 선택 테스트도 관리 객체를 수정한 뒤 선택 상태를 새로 만들어 캐시가 실제 작성값을 반영하도록 바로잡았다. 재검사에서는 12개 모두 통과했다.

변경 전 파일 4,169개를 비교했으며 기존 파일 중 변경된 것은 `NpcSequenceDrawer.cs` 하나다. 별도 기준으로 CSV 48개도 동일함을 확인했다. 테스트 소스와 meta만 추가했고 런타임·씬·저장 형식은 바꾸지 않았다.

임시 검증 도구 제거 후 최종 컴파일·어셈블리 재로드도 성공했으며, 실제 수리공 Inspector에서 기존 배치·라벨과 상대 X=0.525/Y=0·이동 1.1초·페이드 0.5초 표시를 확인했다.

근거: `Logs/NpcInspectorInternal/final-validation.json`, `Logs/NpcInspectorInternal-final-tests.xml`, `Logs/NpcInspectorInternal/asset-check.json`, `Logs/NpcInspectorInternal/final-compile.log`. 첫 검사 기록은 `Logs/NpcInspectorInternal-verification-tests.xml`에 보관한다.
