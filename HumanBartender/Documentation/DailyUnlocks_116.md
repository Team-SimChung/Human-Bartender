# #116 일차별 신규 재료·레시피 안내

## 동작과 소유권

`PlayPhaseController.RunDayAsync`에서 데이터 로드, 정산 시작, 체크포인트 캡처를 마친 뒤 개점 대사 전에 확인을 기다린다.
0일차 또는 신규 항목이 없는 날에는 기다리지 않는다. 별도 확인 완료 플래그는 저장하지 않으므로 재입장·영업 재시작 때 다시 표시된다.

`DailyUnlockQuery`는 원본 순서를 유지한다. 그 일차의 재료 중 조건부 항목을 제외하고, 칵테일은 기존 `CocktailUnlockPolicy`를 재사용한다.
모델은 `struct`이므로 항목 null 검사를 하지 않으며 null 목록과 기본 `DailyUnlocks` 값은 빈 목록으로 취급한다.

`DailyUnlocksScreen`은 표시·카드 재사용·확인 대기만 소유한다. 입력 맵, 시간 배율, 진행 플래그는 바꾸지 않는다.
일시정지가 열려 있으면 확인을 무시한다. 키보드 포커스는 팝업 안에서만 이동하며 목록 밖 카드를 선택하면 해당 카드가 보이도록 스크롤한다.
이미지가 없으면 ID를 포함한 경고와 Inspector의 Fallback Sprite를 사용한다. 대체 이미지도 비어 있으면 아이콘을 숨기고 이름은 표시한다.

## 현재 콘텐츠 기준

사용자가 기존 대사 효과 보존과 웹 CSV 전체 반입 보류를 선택했다. 현재 1일차에는 `ginger_ale`와 `moscow_mule`이 포함되어 재료 8개·칵테일 5개다. 원래 계획의 7개·4개는 웹 e026c0e 반입 이후 기준이므로 이번 완료 기준에 사용하지 않는다. 런타임에 이 두 ID를 제외하는 예외를 추가하지 않는다.

## 사용자 셋업

1. Unity 6000.3.14f1에서 `Assets/01.Game/01.Scenes/Play.unity`를 연다.
2. `Tools/Human Bartender/UI/Setup Daily Unlocks`를 실행한다.
3. `05.UI/Canvas_DailyUnlocks`의 Inspector와 화면 구조를 확인한다. 필요하면 Fallback Sprite를 지정한다.
4. 확인 후 Play 모드를 끈 상태에서 씬을 저장한다.

메뉴는 Play 모드와 다른 활성 씬에서 실행을 거부한다. 기존 캔버스·카드 프리팹이 있으면 배치나 사람이 연결한 값을 덮어쓰지 않는다.
처음 실행할 때만 카드 프리팹을 생성하고, 사용한 Multiple 스프라이트의 테두리가 0인 경우 개별 SpriteRect에 9-slice 경계를 설정한다.
기존 Sprite ID와 원본 이미지 파일은 유지한다. 누락된 이미지·폰트·카탈로그는 경고하고 빈 참조로 남긴다.
셋업은 씬을 자동 저장하지 않는다. 캔버스는 GimmickRunner/CraftPrepStageHost의 `barCanvases`에 넣지 않는다.

## 검증

자동 테스트: `Assets/01.Game/06.Tests/Editor/DailyUnlocksTests.cs`.

- 조회 규칙, 원본 순서, null 목록, 0일차, 현재 Unity CSV 1일차 재료 8개·칵테일 5개.
- 카드 재사용, 설명 줄, 확인 완료, 취소·비활성화 후 재진입, 중복 호출, 렌더 실패 정리, 이미지 누락 대체, 일시정지 중 확인 차단.
- 저장된 Play 씬의 캔버스·연결과 카드 프리팹 UI 규칙. 이 두 검사는 사용자 셋업·저장 전에는 실패한다.

수동 검증:

1. PlayFlowManager의 PlayPhaseController에서 Test Day를 1로 설정하고 직접 Play한다.
2. 재료 8개·레시피 5개와 기본 설명 문구를 확인한다.
3. 포인터 진입과 방향키 선택으로 설명이 바뀌는지 확인한다.
4. Esc로 일시정지하고 확인 입력이 무시되는지 확인한다. 일시정지를 닫고 확인하면 개점 대사가 시작되어야 한다.
5. Test Day 0에서는 화면이 없고, Test Day 2에서는 스크롤과 스크롤 밖 카드의 키보드 선택을 확인한다.
6. Game 창 1280×720 / 1920×1080 / 2560×1440에서 중앙 배치와 글자를 확인한다.
7. 테스트용 Test Day 값을 원래 값으로 돌려놓는다.

코드 컴파일, 자동 검사, 저장된 씬 검사, 실제 플레이·해상도 확인은 서로 다른 검증 단계다. 사용자 셋업 전에는 씬 연결과 실제 플레이를 완료로 간주하지 않는다.
