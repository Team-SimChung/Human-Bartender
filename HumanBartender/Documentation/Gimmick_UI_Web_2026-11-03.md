# 기믹 진행 UI와 웹 리소스 대조

기준 저장소: [junseo874/junseo874.github.io](https://github.com/junseo874/junseo874.github.io/tree/24022cdec49a23200d5500a3e8deef931267206d/bar-playtest), 커밋 `24022cdec49a23200d5500a3e8deef931267206d`.

## 리소스 확인

- 기믹 UI 이미지, 배경, 캐릭터 시트, 병따기 도구·병맥주, 따르기 잔을 합쳐 154개를 대조했다.
- 135개는 Git blob SHA-1이 같다. `cup3.png`는 파일 인코딩이 다르지만 크기 160×270과 디코딩한 RGBA 픽셀이 전부 같다.
- 없는 18개는 `WebGenerated/Combined`의 합성 미리보기다. 대응하는 런타임 배경·테두리·그림 파일은 프로젝트에 있다.
- 원본 PNG를 덮어쓰거나 새로 만들지 않았다. 상세 목록과 원본 해시는 `Gimmick_UI_Web_2026-11-03.assets.json`에 기록했다.

## 적용한 구성

| 화면 | 변경 |
| --- | --- |
| 공통 HUD | 1280×720 무대를 균등 배율로 표시. 우측 상단 시계 아이콘·제조시간을 웹 크기와 여백으로 배치. |
| 따르기·필업 | 좌측 상단에 목표량/현재량을 분리하고 레시피 단위(oz/ml)로 표시. 좌측 하단에 번역된 재료 이름, 상단 중앙에 실제 병 각도와 유량 임계각을 반영한 기울기 게이지. 우측 하단에 웹 원본 버튼 그림을 사용한 ‘따르기 마치기’. 목표를 숨기는 기존 규칙은 유지. |
| 스터 | 원본 `BG_stir` 전체 배경, 웹의 캐릭터 창·확대창·원형 입력판·하단 결과 게이지 배치. 원본 A/B/C 키캡과 원형 게이지 연결. 첫 입력 안내를 진행판 안에 표시. 공통 수량/재료/다음 버튼의 중복 표시 제거. |
| 대체 리듬 셰이크 | `RhythmShakingMinigame.prefab`에 웹 진행판 배경·도트·스캔라인 이미지를 연결하고 기존 A/D 콘텐츠를 균등 배치. 본편의 Shake 참조는 기존 `NewShakingMinigame.prefab`을 유지한다. |
| 병따기 | 기존 웹 병따기 구성을 유지하고 공통 제조시간만 같은 위치에 표시. 중복 재료 ID 표시는 감춤. |

`Play.unity`, `NewStirGame.prefab`, 개발용 `Stir.unity`, `RhythmShakingMinigame.prefab`에 구성을 저장했다. 판정·점수·유량·게임 진행 데이터는 변경하지 않았다.

별도 개발용 `CraftPrep.unity`는 기존 HUD 참조·좌표계를 유지한다. 새 수량 패널 참조가 없는 HUD는 기존 진행 문구·버튼·시계 배치로 동작하도록 호환 처리했다.

실제 실행 프리팹과 기믹별 동작·입력·종료 경로는 [현재 기믹 시스템 문서](Gimmick_System_Current.md)를 참고한다. 본편 셰이크와 준비된 A/D 리듬 구현은 서로 다른 프리팹이다.

## 검증

- 프로젝트의 Unity 컴파일 응답 파일과 참조 어셈블리로 런타임 전체 및 에디터 전체 C# 컴파일 통과.
- 직렬화 ID 중복, 부모·자식 연결, 원본 스프라이트 참조 및 재실행 시 변경 없음 확인.
- 리소스 검사 통과: 파일 동일 135개, 픽셀 동일 1개, 런타임 원본 누락 0개.
- 컴퓨터 사용 없이 파일과 코드로 적용했다. Unity 플레이 모드에서 화면과 조작을 직접 확인하는 검증은 미실행이다.

프로젝트 폴더에서 재검사:

```text
node Tools/UI/audit-gimmick-assets.cjs
node Tools/UI/align-gimmick-ui.cjs --check
```

구성을 다시 적용하려면 마지막 명령의 `--check`를 `--apply`로 바꾼다. 열려 있는 씬의 메모리 상태를 저장하지 않으므로, Play 또는 개발용 Stir 씬은 디스크 변경을 다시 불러온 뒤 확인한다.
