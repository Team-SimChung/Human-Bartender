# NPC와 사물의 Inspector 설정

2026-11-07 Home·OutSide 웹 연출 대응 설정 기준이다. 기존 대사·CSV 조건·결제·저장 형식은 유지한다. 현재 씬의 배치 위치·크기는 보존하고 그 위치를 기준으로 실행할 동작과 시간을 설정한다.

## 1. 어디에서 무엇을 설정하나

| 컴포넌트 | 담당 |
|---|---|
| `WorldInteractionTarget` | 대화 자동/수동 시작, 시작 범위, 기존 대본 연결 |
| `NpcInteraction` | 등장 조건, 배우 연결, 연출 호출 시점, 동작 목록의 순서·거리·시간 |
| `NpcActor` | 공통 이동·표시·시선·Animator 실행과 취소 시 자세 복원 |
| `NpcMovement2D` | 공통 직선 이동. 기존 속도 방식 동작의 Move Speed |
| `NpcSceneStaging` | 목록이 요청한 루나 위치·방향과 카메라 실행. NPC별 대본·진행 플래그는 보유하지 않음 |
| `WorldDialogueSpeakers` | 기존 CSV 화자와 말풍선 앵커 연결 |

여러 NPC가 등장해도 사건 루트의 Interaction 하나가 각 배우를 관리한다. 각 배우는 NpcActor·NpcMovement2D·Animator를 갖는다. TV·문·엘리베이터처럼 NPC 행동이 필요 없는 사물은 기존 WorldInteractionTarget 출력과 Action/Timeline을 사용한다.

## 2. 자동/수동 대화 시작과 범위

대상 루트의 `World Interaction Target`에서 설정한다.

| Start Mode | 의미 |
|---|---|
| 직접 상호작용 | 범위 안에서 상호작용 입력 시 시작 |
| 범위 진입 시 자동 시작 | CSV 조건과 범위를 만족하면 자동 시작. 연출 중 입력 잠금 |
| 주변 대화 · 이동 허용 | 대사 전용 주변 대화. NPC 동작 목록과 함께 사용하지 않음 |
| 다른 사건에서만 호출 | 범위·직접 입력 대신 다른 사건의 연결에서 시작 |

`Interaction Radius`는 대상 루트와 루나 사이 월드 XY 거리다. 선택하면 Scene 뷰의 청록색 원으로 확인한다. 기존 수리공·경비원은 직접 상호작용/1.4, 1일차 불량배는 자동 시작/2다. 이번 적용은 사용자가 작성한 시작 방식·범위를 덮어쓰지 않는다.

CSV의 일차·출퇴근·조건·완료 플래그는 계속 대화 가능 여부를 판단한다. `Content Start Overrides`는 interact_points의 특정 행 ID에 대한 시작 방식 예외다. source ID를 넣는 필드가 아니다.

## 3. 실행 방식과 CSV 연결

연출 목록의 **실행 방식은 이 동작 목록을 무엇으로 호출하는지**다. 대화를 자동으로 시작할지는 앞 절의 Start Mode가 정한다. `CSV · 연출 ID로 호출`과 `CSV · 등록된 명령으로 호출`은 모두 CSV 대본에서 호출하는 방식이다. 두 방식 모두 이동 거리·시간·페이드 등 실제 동작은 Inspector의 `동작 순서`에 저장된 값을 사용한다.

| 실행 방식 | 코드 값 | 호출 방법 |
|---|---|---|
| CSV · 연출 ID로 호출 | `Named` | CSV 단계 `type=npc-sequence`의 `arg`와 Inspector의 `연출 ID`가 같은 목록을 호출 |
| CSV · 등록된 명령으로 호출 | `WorldAction` | CSV 명령을 코드에 등록된 명령으로 변환하고, Inspector의 `등록된 CSV 명령` 선택 값과 같은 목록을 호출 |
| 대화 정상 종료 후 실행 | `DialogueCompleted` | 대화 정상 종료 뒤 조건이 맞는 목록들을 실행 |
| 대화 시작 전 실행 | `BeforeDialogue` | 세션·입력 잠금 확보 뒤 첫 대사 표시 전에 실행. 루나 정렬·카메라 준비에 사용 |

`CSV · 연출 ID로 호출`에서는 예를 들어 CSV에 `type=npc-sequence`, `arg=guard-leave`를 작성하고 Inspector의 `연출 ID`도 `guard-leave`로 정한다. 현재 공통 동작을 조합하는 새 연출이라면 ID를 코드에 추가하지 않아도 연결할 수 있다.

**등록된 CSV 명령 메뉴는 코드에 미리 정의된 명령 목록**이다. CSV 파일에서 메뉴 항목이나 동작 수치를 읽어 만드는 기능이 아니다. 예를 들어 CSV의 `notion-action` / `dealer-exit`은 `NotionDealerExit`으로 변환되어 Inspector의 `계약 밀수업자 · 퇴장` 선택 값과 비교된다. 이 방식에서는 `연출 ID`를 CSV 명령과 비교하지 않는다. 새 명령 종류를 등록하려면 코드 연결이 필요하다. 메뉴를 선택한다고 CSV에 명령이 추가되거나 그 NPC에게 모든 기능이 생기지는 않는다. 해당 대본에서 실제로 요청하는 명령만 연결한다.

수리공의 repair는 `실행 방식 = CSV · 등록된 명령으로 호출`, `등록된 CSV 명령 = 수리공 · 엘리베이터 수리`다. CSV가 수리를 요청한 순간 목록이 실행된다. repair-complete는 `대화 정상 종료 후 실행`이므로 등록된 CSV 명령을 선택하지 않는다. 불량배 카메라 준비는 `대화 시작 전 실행`, 대사 사이 타격은 `CSV · 등록된 명령으로 호출`을 쓴다.

| 등록된 CSV 명령 메뉴 | 코드 값 | 용도 |
|---|---|---|
| 수리공 · 엘리베이터 수리 | `RepairElevator` | 지급 후 수리 연출 |
| 부비 · 입양 | `AdoptCat` | 입양 및 집으로 이어지는 전환 경계 |
| 부비 · 발견 | `RevealCat` | 상자에서 부비 발견 |
| 부비 · 쓰다듬기 | `PetCat` | 쓰다듬기 반응 |
| 부비 · 먹이 | `FeedCat` | 먹이 반응 |
| 이웃 · 등장 | `NeighborEnter` | 이웃 표시·접근 |
| 이웃 · 퇴장 | `NeighborExit` | 이웃 퇴장 |
| 크리스 · 등장 | `ChrisEnter` | 취침 대본의 등장·카메라 |
| 부비 · 울음 | `CatMeow` | 집 부비 울음 |
| 출근 삼호 · 퇴장 | `SamhoDepart` | 2일차 출근 삼호 퇴장 |
| 계약 삼호 · 루나에게 접근 | `NotionApproach` | 3일차 계약의 approach |
| 계약 밀수업자 · 퇴장 | `NotionDealerExit` | 계약 중 밀수업자 퇴장 |
| 계약 삼호 · 퇴장 | `NotionSamhoExit` | 계약 후 삼호 퇴장 |
| 불량배 · 타격 | `ThugPunch` | 1일차 거절 분기 타격 |
| 불량배 · 퇴장 | `ThugDepart` | 1일차 불량배 퇴장 |
| 공통 · 문 효과 | `DoorCue` | 기존 사건의 문 효과 요청 |

한 Interaction 안에서 `연출 ID`는 중복시키지 않는다. `CSV · 등록된 명령으로 호출` 목록끼리는 같은 `등록된 CSV 명령`을 중복 연결하지 않는다. 실행 조건을 비우면 추가 제한이 없다. BeforeDialogue·DialogueCompleted는 조건이 참인 목록만 실행한다. 연출 ID·등록된 명령으로 직접 호출했는데 연결이 없거나 조건이 거짓이면 구성 오류다.

Sequences 배열 순서가 대사 사이 CSV 명령 순서를 바꾸지는 않는다. 그 순서는 CSV가 결정한다. **각 목록 안의 동작 순서**는 위에서 아래로 실행하며 앞 동작이 끝날 때까지 기다린다.

## 4. 등장 조건과 시선

| Npc Interaction 필드 | 의미 |
|---|---|
| Use Story Presence | 켜면 CSV 사건 등장·완료 조건으로 배우도 표시/숨김 |
| Minimum Day / Maximum Day | 등장 일차 범위. 마지막 일차 -1이면 제한 없음 |
| Presence Phase | 출근/퇴근/양쪽 표시 제한 |
| Minimum Day Starts On Return | 첫 일차는 퇴근부터, 다음 날부터는 출퇴근 모두 표시 |
| Presence Condition | 추가 표시 조건 |
| Actor Visible Outside Session / Actor Presence Condition | 대표 배우의 평소 표시·추가 조건 |
| Additional Actors | 추가 배우 참조와 각각의 평소 표시 조건 |
| Require Visible Actor To Interact | 대표 배우가 보여야 시작. 발견처럼 처음에 숨긴 사건은 끔 |
| Committed Condition | 중단 시 자세 복원 여부의 진행 기준. 비우면 CSV 완료 플래그 |
| Restore Pose After Interaction | 종료 시 시작 자세를 복원하고 현재 등장 조건을 다시 적용 |

표시 조건을 별도로 두어도 **대화를 시작할 CSV 조건은 유지**된다. 경비원이 남아 있는 것과 통행 대화를 다시 실행할 수 있는 것은 별개다.

| 대상 | 현재 표시 설정 |
|---|---|
| 수리공 | Use Story Presence 끔, 최소1일차, `!flag.elevator_repaired`, 확정 조건 `flag.elevator_repaired` |
| 1일차 불량배 | Use Story Presence 켬, 기존 1일차 출근·미완료 조건 |
| 경비원·보스 일행 | Use Story Presence 끔, 최소0일차, 첫날 퇴근부터 켬. 허가·소개 대화 후에도 배경에 남음 |
| 1일차 삼호·밀수업자 거래 | Use Story Presence 끔, 최소/최대1일차, 퇴근. 완료해도 그날 남고 다음 날 숨음 |
| 시바 상점·재방문 | 최소2일차 + 기존 사건 조건 |
| 외부 부비 | 기존 조건 + 배우 조건 `flag.boobi_revealed`. 이웃은 평소 숨김 |
| 집 부비·크리스 | 입양 조건 유지. 크리스는 평소 숨김, 취침 대본에서 표시 |

집 부비 루트는 활성 상태로 둔다. 표시 여부는 Actor 조건이 관리한다. 기존 Content 기반 bubi·shiba의 비활성 배치와 CSV 조건은 유지한다.

`Npc Actor > Idle Facing`: 배치한 방향 유지 / 플레이어 바라보기 / 연결한 대상 바라보기 중 선택한다. 마지막은 Idle Facing Target을 연결한다. Face Player During Dialogue를 켜면 대화 중 루나를 본다.

삼호·밀수업자는 서로를 본다. 경비원은 평소 보스를, 보스·갱단원은 서로를 보고 직접 대화 중에는 루나를 본다. 목록의 `대상 바라보기`는 해당 대화 동안 시선을 지정한 대상으로 전환한다. 계약 중 삼호가 루나를 계속 보는 데 사용한다.

## 5. 동작 목록 작성

Sequences에서 `연출 ID`·`실행 방식`·`실행 조건`을 정한 뒤 `동작 순서`를 작성한다. `실행 NPC`를 비우면 대표 Actor, 추가 배우를 넣으면 그 배우가 실행한다. `대상`은 이동·시선의 기준이며 비우면 루나다.

| 동작 | 설정 |
|---|---|
| 상대 이동 | 현재 위치 + X/Y. Move Speed 사용 |
| 대상에게 접근 | 멈출 X 간격만큼 남김. 이미 가까우면 물러나지 않음. Move Speed 사용 |
| 기준 위치로 이동 | 현재/처음 배치/대상/월드 원점 + X/Y. 이동 시간 또는 속도·이동 변화 설정 |
| 기준 위치에 배치 | 같은 기준으로 즉시 배치. 숨긴 배우도 가능 |
| 포물선 이동 | 목적지까지 지정 시간에 이동하며 지정 높이로 솟았다 내려옴 |
| 대상 바라보기 | 해당 대화 동안 대상 쪽 시선 유지 |
| 애니메이션 재생 | Animator 상태·복귀 상태·재생 시간. 비반복 클립 사용 |
| NPC 표시 / NPC 숨김 | 선택한 배우만 표시/숨김 |
| 대기 | 다음 동작까지 기다리는 시간 |
| 화면 암전 / 화면 복귀 | 화면 전체 페이드 |
| 페이드 후 숨김 | 배우만 제자리 페이드 |
| 이동 후 퇴장 | Move Speed로 상대 이동을 끝낸 뒤 배우 페이드 |
| 이동하며 페이드 퇴장 | 상대 X/Y 전체를 이동하고 마지막 구간은 페이드 동시 실행 |
| 목적지로 이동하며 퇴장 | 기준 위치의 목적지로 이동하면서 마지막 구간에 페이드 |
| 플레이어 위치 맞추기 / 위치 설정 | 루나를 시간에 맞춰 이동 / 즉시 배치 |
| 플레이어 바라보기 방향 | 루나가 대상 + X/Y 보정 위치를 보게 함 |
| 카메라 구도 맞추기 | 지정 중심·가로 범위로 웹 방식 추적. 최소 시간과 정착 조건을 모두 만족하면 종료 |
| 카메라 이동 | 지정 시간·곡선의 팬. 동시에 화면 복귀 값으로 암전 해제 병행 가능 |
| 카메라 구도 즉시 설정 | 암전 중 팬 시작점 준비 등에 사용 |
| 카메라 추적 복귀 | 루나 현재 위치를 따라가는 원래 카메라로 복귀 |
| 효과음 / 목표 완료 알림 | 기존 효과음 이름 / 알림 문구 |

부비 Animator의 기존 `PulseFeed`, `PulsePet`, `PulseReveal` 이름도 각각 `Feed`, `Pet`, `RevealEyes`와 같은 프레임 클립에 연결한다. 기존 목록의 상태 이름은 계속 사용할 수 있으며, 루트 크기를 늘리는 곡선은 사용하지 않는다. 발견 뒤 점프 이동은 별도 `포물선 이동` 동작이 맡는다.

`X만 이동`은 Y/Z를 유지한다. `이동 속도 (0이면 시간 사용)`가 0이면 이동 시간을 사용하고, 양수이면 거리÷속도로 계산한다. 이동은 작성한 월드 좌표 경로이며 경로 탐색을 하지 않는다.

`X 이동 방향 기준`: 작성한 X/Y 그대로는 부호 그대로, 대상의 현재 같은 쪽은 대상 기준 현재 서 있는 쪽에 절댓값 X 간격, 대상 반대 방향으로는 상대 퇴장에서 루나에게서 멀어지는 방향이다. Y는 입력값 그대로다.

`이동하며 페이드 퇴장`의 전체 시간 = 페이드 전 이동 시간 (초) + 이동 중 페이드 시간 (초)이다. 전체 이동량÷전체 시간이 속도이며 Move Speed를 쓰지 않는다. 페이드 변화는 투명도에만 적용하고 이동은 일정한 속도다. Exit Point 없이 X=4이면 명령 당시 X에4를 더한다. 화면 암전 시간과 배우 퇴장 페이드는 독립적이다.

MoveTo·MovePlayer의 `이동과 함께 카메라 맞추기`는 이동·카메라를 병행한다. 대상과 플레이어 중간 구도·카메라 중심 보정 X/Y·가로 범위를 설정한다. 현재 강제 사건 가로 범위는4.8이다. 임의의 여러 NPC 동시 이동을 지원하는 병렬 목록은 아니다.

화면 암전과 복귀는 같은 목록에 둔다. 중단·오류 시 검은 화면이 남지 않도록 복귀한다. SceneStaging은 취소 시 루나 시작 위치·방향과 카메라를 복원한다. 성공하면 루나 도착 위치를 유지하고 카메라는 원래 추적으로 돌아간다. NPC 최종 자세·표시는 Interaction의 완료·등장 조건을 따른다.

## 7. 도구와 보존 범위

`Tools/Story/Apply Web NPC Presentation`은 Home·OutSide 웹 대기 프레임·반응·시선·목록을 설정하고 씬을 저장한다. 재실행하면 대상 명령의 웹 동작·시간·시선을 다시 설정하므로 평소 편집은 Inspector에서 한다. 수리공 기존 상대 퇴장 X/Y와 목표 알림은 보존한다.

`Migrate NPC Interaction Sequences` / `Migrate All Home and Outside NPCs`는 최초 이전 도구이며 이미 있는 Interaction을 덮어쓰지 않는다.

`Apply Web Day 3 Contract Motion`은 계약의 접근·밀수업자 퇴장·삼호 퇴장 세 명령을 재설정한다. 전체 웹 적용 도구와 같은 공통 기본값을 사용하므로, 삼호 접근에 병행하는 카메라 설정도 함께 적용한다. 대화 시작 전 루나 정렬과 종료 카메라 복귀 목록까지 재적용하려는 경우에는 `Apply Web NPC Presentation`을 사용한다.

등록된 명령에 이미 연결된 목록을 갱신할 때는 사용자가 작성한 연출 ID와 실행 조건을 보존한다. 대상이 아닌 추가 목록도 유지한다. 다만 해당 목록 안의 동작·거리·시간은 웹 기본값으로 다시 작성하므로, 사용자 수치를 조절하는 일상 작업은 Inspector에서 한다. 초기 설정 도구의 공통 기본값은 실행 중 읽는 데이터가 아니며, 실제 플레이에서는 씬에 저장된 목록을 사용한다.

설정 도구는 같은 직렬화 경로로 모든 동작 필드와 배우 참조를 읽고 쓴다. 부비 스프라이트 가져오기는 Sprite Editor Data Provider를 사용하며, 같은 이름의 기존 Sprite 식별자는 유지한다. 리팩토링 코드를 반영하는 것만으로 씬 설정이나 그림 자산을 재생성하지는 않는다.

기존 대사·CSV·선택·결제·저장 플래그/형식, Inspector 시작 방식·범위, 배치 위치·크기, 수리공 상대 X/Y를 유지한다. 동작 목록·시선·배경 표시·Animator 클립은 갱신한다. 웹의 별도 정적 NPC 위치 보정까지 Unity 배치에 덮어쓰지는 않는다. 새 공격 그림·피해 판정·넉백은 추가하지 않았다.

## 8. 실행 책임 리팩토링과 Inspector 표시 원복

사용자 요청으로 이번에 추가한 Inspector 시각 변경은 되돌렸다. `Npc Interaction`의 루트 필드는 기존 `Actor`, `Additional Actors`, `Sequences` 표시를 사용하며, 동작 목록도 변경 전 한 줄 배치와 기존 라벨을 사용한다. 짧은 라벨·좁은 창의 위아래 배치·X/Y 별도 줄은 적용하지 않는다. 앞서 정리한 `연출 ID`, `실행 방식`, `등록된 CSV 명령`과 두 CSV 호출 방식 이름도 유지한다.

이후 표시 배치를 유지하는 내부 정리를 적용했다. 동작 제목은 기존 enum의 표시 이름을 사용하며, 등록된 CSV 명령은 목록의 위치가 아닌 명령 값으로 연결한다. 여러 NPC의 명령이 다르면 혼합값으로 표시하고 사용자가 변경할 때만 기록한다. 실행 방식이 서로 다르면 명령 선택을, 동작 종류가 서로 다르면 종류별 상세 설정을 공통 값으로 맞추기 전까지 숨긴다. 혼합된 연출 ID·동작 제목에는 첫 NPC의 값 대신 기본 항목 이름을 표시한다. 한 NPC를 선택했을 때의 항목명·순서·툴팁·배치는 그대로다.

수리공의 `전체 월드 X/Y 이동량`은 명령 당시 위치에 더하는 상대 월드 이동량이다. `페이드 전 이동 시간 (초)`와 `이동 중 페이드 시간 (초)`의 합이 이동하며 퇴장하는 전체 시간이며, 마지막 페이드 구간에도 이동한다. 화면 암전·대기·화면 복귀는 repair 목록의 별도 동작으로 유지한다. 표시 원복은 씬에 저장된 연결·동작·수치를 바꾸지 않는다.

`NpcSequenceExecutor`는 동작 실행·좌표 계산과 화면 복구를, `NpcSequenceValidator`는 목록의 연결·수치 검사를 담당하는 일반 C# 보조 객체다. 둘 다 씬에 추가하거나 Inspector에서 연결하는 컴포넌트가 아니다. `NpcInteraction`이 기존 설정을 보관하고 연출마다 실행기를 생성하며, 대화 세션·취소·등장 상태를 조정한다. 배우 행동은 계속 NpcActor가 실행하고, 대사·결제·완료 플래그는 기존 CSV 실행기가 관리한다. 이 실행 책임 분리와 에디터 설정 도구 리팩토링은 유지한다.

리팩토링 검사 당시에는 재검사를 반영해 서로 다른 98개 검사가 통과했고, 씬·CSV·기존 리소스 참조 파일 3,536개는 보존 기준과 동일했다. 이 기록은 Inspector 표시 원복 이전 결과이며, 새 레이아웃의 화면 확인 결과를 현재 Inspector의 검증 결과로 해석하지 않는다. 단계별 결과와 테스트 타이밍 보완 내용은 [리팩토링 검증 기록](Npc_Refactor_Verification_2026-11-07.md)과 `Logs/NpcRefactor-final-validation.json`에서 확인한다.
