# 변경사항 검토 결과 — 2026-11-06

현재 작업 트리의 기믹 UI 편집 전환, 따르기 전용 HUD, 손님 타이머 정지 범위를 검토했다. 코드·직렬화 참조·에디터 테스트·렌더링·Windows 플레이어용 스크립트 컴파일을 확인했다.

## 발견해서 수정한 내용

| 항목 | 문제와 수정 |
| --- | --- |
| 셰이크 진행 게이지 | 설정은 20회지만 프리팹은 15칸이어서 마지막 5회를 표시하지 못했다. 프리팹에 20칸과 강조 테두리를 저장하고 `ResetJudgement()`에서 실제 목표 수로 활성 칸을 설정한다. 색상 방식의 게이지도 `Configure()`가 적용된다. 실행 중 UI 생성이나 자동 재배치는 하지 않는다. |
| 에디터 씬 보존 | 전체 UI 저장 도구가 개발 씬을 Single 방식으로 열어 작업 중인 씬을 닫을 수 있었다. Additive 방식으로 필요한 씬만 열고, 원래 열려 있던 씬·미저장 변경·활성 씬을 보존하도록 바꿨다. |
| 에디터 재실행 | 따르기 설정 도구를 다시 실행하면 기존 병 그림을 강제로 켰다. 이미 배치한 병 그림의 표시 상태를 유지하도록 수정했다. |
| 파일 검사 도구 | 이미 연결된 HUD의 Unity 자동 저장 Canvas 배율을 검사 스크립트가 다시 쓰려 했다. 연결이 완성된 HUD는 Canvas 배율과 수동 Canvas Scaler 설정을 보존한다. |
| 병따기 언어 | 프리팹 전환 후 다음 버튼 문구가 한글로 고정됐다. 현재 언어에 따라 ‘다음 → / Next →’를 갱신하도록 복원했다. |

## 확인한 동작

- 따르기·필업은 `NewPourGame/Pour HUD/Panel`의 저장된 UI를 사용한다. 공통 HUD와 중복 표시하지 않고 같은 제조 시계·시간 숨김 규칙·튜토리얼 강조 대상·마치기 버튼을 연결한다.
- 목표선은 시작할 때 한 번 계산하며 실시간 수면 보정은 꺼져 있다. 수량은 도착해 잔 안에 남은 액체를 세고 넘친 양은 제외한다.
- 손님 시계는 재료 선택부터 기믹·결과 화면을 거쳐 제공하기까지 정지한다. 취소·폐기 완료 시 재개하고 재시도 중에는 정지를 유지한다. 제조 점수용 시계는 별도로 진행한다.
- 병따기·스터·셰이크·따르기의 편집한 자식 UI 위치는 실행 또는 에디터 설정 재실행으로 초기화되지 않는다.
- Play/개발 Stir 씬과 4개 실행 프리팹에서 중복 fileID·누락된 내부 참조를 발견하지 못했다. 프로젝트 GUID 중복 0개, 외부 패키지 참조 29개 모두 정상 해석됐다. 실행 프리팹의 누락 스크립트와 필수 UI 참조도 검사했다.
- `ProjectLifeScope.prefab`의 현재 차이는 줄 끝 공백/개행을 제외하면 런타임 내용 변경이 없다.

## 검증 결과

- 서로 다른 테스트 **120개 최종 통과**. 첫 통합 실행은 118개 통과, 애니메이션 2개 실패였다. 두 실패는 검증용 프로젝트의 초기 `-nographics` 임포트가 10,240px 스프라이트 시트를 처리하지 못해 생긴 캐시 문제였다. D3D11 환경에서 다시 임포트한 뒤 두 검사가 모두 통과했고, 16개 프레임의 참조 누락은 0개였다. 원본 스프라이트 파일·메타데이터는 수정하지 않았다.
- Windows Standalone 플레이어용 스크립트 컴파일: **50개 어셈블리 생성 성공**. 에디터 전용 코드가 제외된 컴파일도 확인했다. 전체 게임 패키지를 빌드한 결과는 아니다.
- UI 표시와 화면 범위는 1280×720, 1920×1080, 1024×768에서 검사했다.
- 반복 수량 측정과 병 드래그의 관리 힙 할당은 0바이트였다.

## 성능 확인 범위

이 검증 환경에서 입자 2,000개일 때 SPH 물리 한 스텝은 평균 약 **13.03ms**, 수량 집계는 약 **0.30ms**였다. 이번 UI 변경으로 액체 물리 자체의 비용이 줄어든 것은 아니다. 전체 Play 씬의 실제 입력·출수·렌더링을 함께 실행한 FPS 측정은 이 결과에 포함하지 않는다.

셰이크 목표 시도 수를 프리팹에 저장한 칸 수보다 늘리려면 칸과 강조 테두리도 함께 추가해야 한다. 부족하면 오류를 표시하며 실행 중 UI를 생성하지 않는다.

검증 로그와 결과 XML은 `Logs/ChangeReview`에 보관했다. 원래 열려 있는 Unity 편집기를 조작하지 않고 복사한 프로젝트에서 실행했다.
