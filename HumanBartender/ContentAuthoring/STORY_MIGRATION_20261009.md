# 0–3일차 최신 스토리 이식

웹 프로젝트의 실제 캠페인에서 사용하는 대사와 선택지를 유니티 CSV로 교체했다. 실행은 기존 C# 대화·제조·서빙 시스템을 사용한다. 웹 JavaScript 파일이나 JavaScript 실행기는 유니티에 추가하지 않았다.

원본: `junseo874.github.io/bar-playtest`의 `data.js`, `campaign-data.js`, `campaign-engine.js`, `outside-dialogue-data.js`, `outside-notion-20261005.js`, `outside-thug.js`, `outside-shop.js`, `bd-vendor.js`, `cinematic/scene5.js`. 1–3일차는 정적 원본만 보지 않고 캠페인 엔진이 교체한 실제 대본을 기준으로 했다.

## 플레이 경로

| 일차 | 바 일반 대사 | 집 대화 | 주요 외부 대화 |
|---|---:|---|---|
| 0 | 112 | 테라스 | 지명수배 포스터 |
| 1 | 235 | 작업장 → 테라스 | 불량배 입주 비용, 삼호와 밀수업자, 시BAR, BD 판매상 |
| 2 | 111 | 테라스 → 선택적 조니 회상 | 불량배 재회·정보 구매, 삼호 출근길, 시BAR, BD 판매상 |
| 3 | 127 | 테라스 → 데모 종료 | 삼호 출근길·계약 종료, 시BAR, BD 판매상 |

바의 1–3일차는 개점 전 대화 → 기존 영업 → 본편 순서다. 0일차는 새 게임을 Home에서 시작해 출근 후 튜토리얼 대화를 진행한다. 외부 대화는 가까운 위치의 클릭 버튼 또는 기존 스토리 접근 조건으로 시작하고, 대사는 클릭으로 넘긴다. 집에서 소파의 취침을 선택하면 그날 작업장·테라스 대화를 먼저 진행한다. 완료 플래그는 기존 저장 시스템에 보관된다.

선택지는 C# 조건 판정으로 잠금 처리하며, 기존 UI의 칸 수보다 많으면 페이지를 넘겨 모든 선택지를 볼 수 있다. 돈을 내거나 재료를 구매하는 결과는 해당 선택지를 선택했을 때만 적용한다. 자유 주문은 현재 해금된 확정 레시피를 선택해서 기존 제조·서빙으로 진행한다. 개점 전 무료 맥주는 대금을 정산하지 않는다.

3일차 올드 패션드는 와일드 독·비터스 구매와 귀가 후 이야기 확인이 필요하다. 출근 전에 구매할 수 있으며, 아일리의 각설탕 대사 이후 레시피가 열린다. 와일드 독 45ml, 비터스 5ml, 각설탕 1개를 사용한다. 각설탕 조작 기믹은 없으므로 현재 유니티의 자동 재료 처리로 넣고 점수를 매기지 않는다. `add`와 `count`를 추가해 각설탕을 액체 부피로 바꾸지 않았다.

## 컷신과 리소스

컷신 전용 대사는 `script/cutscene`에 따로 보관한다. 루나의 꿈, 조니 회상, 테라스 회상 등의 연출이 없거나 재생에 실패하면 그 안의 대사는 출력하지 않고 다음 일반 대사로 진행한다. 실행 취소는 컷신 누락으로 취급하지 않는다. 미구현 조니 회상으로 다음 일차가 막히지 않도록 회상 시도 후 진행 조건을 처리한다.

| 확인한 부족한 구성 | 현재 처리 |
|---|---|
| Tom의 바 인물 아트, Shiba 등 일부 초상화 Addressables 연결 | 텍스트로 진행하며 화자·좌석·서빙 좌표는 유지 |
| 신규 불량배·정보상·BD 판매상·계약 이벤트 전용 프리팹과 이동 연출 | CSV 위치에 대화 버튼을 표시. 전용 필드 인물/연출 제작은 남아 있음 |
| 테라스·작업장 전용 배경/씬 연결 | 기존 Home 대화 UI로 일반 대사 재생 |
| 꿈·BD·조니·테라스 회상 컷신 연결 | 재생 가능한 컷신 ID가 없으면 스킵. 전용 대사는 보관 |
| 새 올드 패션드·와일드 독·비터스 전용 UI 이미지 | 기존 갓파더·위스키·깔루아 이미지를 임시 연결 |

새 컷신 플러그인 연결 시 사용하는 호출 ID는 `luna-dream`, `bd-memory`, `johnny-memory` 및 원본의 `cinemaAfter` 값이다. CSV에 대사가 있다는 이유만으로 컷신 대사를 일반 대화로 재생하지 않는다. 기존 `INTRO.playable`과 일부 타임라인은 새 캠페인 ID에 자동 연결하지 않았다.

## CSV 편집 위치와 내보내기

- `Assets/StreamingAssets/csv/story/scenes.csv`: 일차, 실행 단계, 실행 씬, 출퇴근 방향, 위치, 완료 플래그.
- `story/steps.csv`: 대사, 조건, 효과, 주문과 컷신 호출.
- `story/bar_choice_groups.csv`, `bar_choices.csv`, `street_choices.csv`: 선택지와 결과 단계.
- `craft/cocktails.csv`, `recipes.csv`, `shelf_items.csv`: 후속 스토리 제조에 필요한 데이터.
- `system/data_sets.csv`, `row_formats.csv`, `columns.csv`: 위 데이터의 구조와 타입.

최신 대본과 직접 연관된 데이터의 정본은 현재 CSV다. 기존 XLSX는 갱신하지 않았다. `csv_owned_datasets.json`에 지정한 14개 데이터 묶음은 엑셀 내보내기 때 현재 CSV를 유지하며, 나머지 묶음은 기존 엑셀 편집 흐름을 사용한다. 지정된 묶음을 변경하려면 CSV를 편집해야 한다.

```sh
python3 ContentAuthoring/export_content.py --source csv --input Assets/StreamingAssets/csv --validate-only
python3 ContentAuthoring/export_content.py --out Assets/StreamingAssets/csv
```

행인·잡담·TV 7개 장면, 53개 대사는 `script/ambient` CSV만 유지한다. 로더·상호작용·자동 대화에 연결하지 않았다. 99일차 QA 데이터 묶음과 기존 거리 대화 참조는 보존했고, 신규 외부 대화와 개점 전 연결은 0–3일차에만 적용한다. 바·집 출입문은 3일차까지 표시한다.

## 확인 방법

Unity의 `Tools/Data/Validate CSV Content`, `Tools/Craft/Validate Craft Data`와 EditMode 테스트를 사용한다. `CampaignStoryTests`는 선택지·레시피 참조, 조건식, 컷신 실패 후 클릭 진행과 취소 처리를 확인한다. 실제 씬 이동 테스트는 `CampaignStoryRuntimeSmokeTests`를 단독 실행한다. 대본 전체를 사람이 클릭하며 모든 제조를 끝내는 시각 검수는 별도 확인이 필요하다.

현재까지 확인한 결과:

- CSV 구조 검사: 38개 데이터 묶음 통과. 엑셀 내보내기도 완료되며 CSV 정본 14개 묶음을 보호한다.
- 실제 씬 단독 테스트: Main → Home → OutSide → Play 이동, 누락된 꿈 컷신 스킵, 바 첫 최신 대사에서 다음 대사로 클릭 진행까지 통과.
- 마지막 일반 EditMode 실행: 90개 통과, 1개 실패, 단독 실행용 2개 제외. 실패는 보존한 기존 QA 결과 단계의 생략된 순번(`seq=0`)을 새 검사에서 중복으로 판단한 건이다. 실행기의 기존 규칙에 맞춰 검사 조건을 수정했다.
- 위 검사 수정의 재실행과 추가 플레이 테스트는 사용자 요청으로 보류했다. 1–3일차 전체 제조·선택지·귀가 경로, 임시 리소스의 화면 배치, 올드 패션드의 실제 제조를 다음 확인 대상으로 남긴다.
