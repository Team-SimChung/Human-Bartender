# 새 게임 진입과 튜토리얼 UI 연결

새 게임은 `Main → Play 씬 입장 → 인트로 → 0일차 튜토리얼`로 시작한다. 인트로는 타이틀이 아니라 Play 씬의 스토리 흐름이 실행한다. `luna-dream` 컷신을 재생하지 못하면 Play 씬에서 전체 화면 안내를 표시하고, 아무 곳이나 클릭한 뒤 튜토리얼 대본을 시작한다. 안내 문구는 다음과 같다.

> 현재 컷신 리소스가 적용되지 않았습니다.
> 아무 곳이나 클릭하면 0일차 튜토리얼로 넘어갑니다.

0일차 시작 단계는 CSV에서도 `bar`다. 0일차는 일반 영업을 건너뛴다. 1–3일차의 귀가·취침·다음 날 출근 흐름은 기존 C# 진행 서비스를 사용한다. 새 게임의 인트로와 바 대본은 씬 전환과 페이드가 완료된 뒤 실행된다.

최초 구현은 Main 씬의 안내 프리팹 참조가 비어 있으면 예외로 멈췄다. 이를 제거했다. Play 씬의 튜토리얼 컴포넌트나 참조가 빠져 있어도 스토리 흐름이 컴포넌트를 생성하고 기존 씬 리소스를 찾아 연결한다. 안내 프리팹이 없거나 내부 UI 참조가 누락되어 있으면 `StoryTutorialView.CreateFallback`이 기존 대화창의 한글 폰트로 안내와 튜토리얼 버튼을 생성한다.

## 확인한 원인과 변경

- 이식된 `story/steps.csv`에서 좌석·코스터 실습이 `effect`로 바뀌어 `arg`가 지워져 있었다. `tutorial: seatExplore`, `tutorial: seatIndicator`, `coaster: tutorial`로 복원하고 C# 실행기에 연결했다. 기존 튜토리얼을 건너뛰는 선택지는 유지한다.
- `CoasterSupplyTray`는 있었지만 스토리 손님은 영업용 `GuestSlot`이 없어 기존 코스터 드롭 영역으로 실습을 완료할 수 없었다. `StoryCoasterDropTarget`으로 실제 드래그를 받고, 놓인 코스터는 첫 주문의 서빙 자리로 이어 쓴다. 주문이 정리되면 트레이로 반환한다.
- 실제 마우스 드래그에서, 처음에는 꺼져 있던 서빙 캔버스를 켜면서 `StoryServeDropTarget.Awake`가 실습 드롭 영역의 입력을 다시 끄는 문제를 확인했다. 캔버스를 활성화한 뒤 `StoryCoasterDropTarget.Bind`를 호출하도록 순서를 수정했다.
- 말풍선 뷰는 새 화자의 말풍선만 켜고 이전 화자의 말풍선을 끄지 않았다. 대사를 넘기는 클릭에서 현재 말풍선을 즉시 닫고, 새 대사가 시작될 때 루나·손님·나레이션 말풍선을 모두 초기화한다. 타이핑 중 첫 클릭은 기존처럼 문장 완성을 처리한다.
- Q/E 바 이동 입력은 일반 영업(Tycoon) 단계만 허용하여 대화 중 좌석 둘러보기 실습에서는 막혀 있었다. 기존 Play 입력 맵의 Q/E를 실습에 연결했다. Q는 왼쪽, E는 오른쪽으로 한 자리 이동하며 이동 중 중복 입력·끝 좌석 밖 이동·키를 놓는 입력은 추가 이동을 만들지 않는다. 안내 패널에 키를 표시하고 좌석 클릭 버튼 대신 키로 실습한다.
- 스토리용 인물 슬롯은 왼쪽·오른쪽만 있어 빈 가운데 자리의 좌표가 없었다. 가운데 인물 슬롯이 있으면 해당 좌표를 사용하고, 없으면 기존 양쪽 인물 슬롯의 중간 좌표로 카메라를 이동한다. 가운데 캐릭터 프리팹을 추가하지 않아도 세 좌석을 둘러볼 수 있다.

## 웹 UI/UX 반영

웹의 `tutorial-view.js/.css`, `bar-views.js/.css`를 참조하여 C# uGUI로 구현했다. JS나 SVG 실행기는 가져오지 않았다.

- `StoryTutorialGuideGraphic`: 안내 대상 외의 화면을 어둡게 하고 대상에는 민트색 테두리와 맥동 효과를 표시한다. 클릭 안내에는 화살표, 코스터 공급 트레이→책상 드롭 영역에는 움직이는 점선 경로를 표시한다. 그래픽은 입력을 가로채지 않는다.
- `StoryTutorialView`: 화면 상단의 큰 설명 상자 대신 대상 가까이에 폭 320의 짧은 안내 상자를 둔다. 좌석 상태 설명은 6개 샘플 점과 설명 카드·현재 좌석 테두리가 있는 창으로 표시한다.
- `BarSeatStatusView`: 좌하단의 3개 점을 실제 스토리 인물과 영업 손님 상태에 연결한다. 빈 좌석은 회색, 손님은 하양/민트, 새 손님은 2.4초간 점멸, 기다리는 시간이 절반 이하이면 주황, 10초 이하이면 빨강, 퇴장 중이면 빨강 점멸로 표시한다. 영업의 기존 대기 시간 시계를 읽으므로 제조 중 멈추는 인내심과 같은 기준을 사용한다. 현재 보고 있는 좌석은 외곽 테두리로 표시하고 레시피·제조 화면에서는 HUD를 숨긴다.
- 바 둘러보기는 사용자 지정에 따라 웹의 A/D 대신 Q/E를 사용한다. 해당 키·좌석 HUD를 함께 강조하고 다음에 둘러볼 방향으로 안내를 갱신한다.
- 코스터 3개의 클릭 영역을 72×72로 확장하여 오른쪽 아래 제공 박스·문구에서도 드래그를 시작할 수 있다. 아이콘의 비율은 유지한다. 드래그용 최상위 캔버스 참조가 비어 있으면 실제 부모 캔버스를 사용한다.
- 레시피 행, 제조 준비의 노트 열기·닫기, 잔·진·탄산수·병따개, 재료 제거·선반 이동·제조 시작 버튼은 현재 단계에 맞춰 강조한다. 제조 준비에서는 안내 순서를 완료해야 시작 버튼을 누를 수 있다.

기존 기믹 화면의 조작은 Unity 입력을 유지한다. 웹과 같은 모든 단계의 클릭 제한과 기믹 내부의 세부 대상 강조까지 이번에 추가하지는 않았다.

초반 컷신의 새 호출 ID 연결과 연출 리소스는 여전히 필요하다. 기존 `INTRO.playable`이 파일로 존재해도 `luna-dream`으로 등록되어 있지 않으면 안내 화면으로 진행한다. 컷신 전용 대사는 안내 화면에서 재생하지 않는다.

행인·잡담·TV는 앞서 추가한 CSV만 유지하며 코드 연결은 추가하지 않았다.

## 검증 범위

- CSV 구조·연결·타입: 38개 데이터 묶음 검증 통과.
- 새 게임의 바 진입 대기, 실패 시 이전 상태 복원, 0–3일차 시작 단계 검사: 관련 EditMode 3개 통과.
- 실제 Main/Play 씬 테스트 2개 통과: 정상 프리팹 연결과 튜토리얼 컴포넌트·프리팹 참조를 비운 경우를 따로 확인했다. 안내가 Play 씬에서 표시되고, 화면 좌표의 UI 레이캐스트와 클릭으로 첫 대사·범례 확인에 이어진다. 좌석 실습은 키보드 상태 이벤트를 기존 Play 입력 맵에 전달하여 Q/E로 세 자리를 이동하고 크리스 자리 복귀 뒤 진행함을 확인했다. 가운데 카메라 좌표, 끝 좌석의 이동 제한, 키를 놓을 때 추가 이동이 없는 것도 확인했다. 코스터 실습은 드롭 함수를 직접 호출하지 않고 실제 마우스 상태 이벤트를 게임 입력 루프로 전달했다. 제공 박스·문구에서 드래그가 시작되고 책상 위 영역에 놓인 코스터가 고정되며 다음 대사로 이어짐을 확인했다. 좌석 HUD의 선택 테두리, 대상 강조, 2단계 색상·점멸 범례도 검사했다. 진토닉 준비 UI·기믹 진입까지 통과했다.
- 최신 실제 씬 테스트 2개는 1280×720의 16:9 게임 화면에서 통과했다. 레시피 창 닫기 → Tab 재열기·다시 닫기 → 메뉴 버튼 재열기, 제조 준비 취소 → Tab 재열기 → 같은 진토닉 실습 재시작을 확인했다. 기다리는 주문과 레시피 제한이 유지되고 Tab 키를 놓을 때 중복 토글하지 않는다.
- 첫 크리스 등장과 퇴장의 중간 알파값, 페이드 도중 RGB 색 유지, 퇴장 완료 뒤 리소스 정리를 검사했다. 랜덤 손님 등장 중 취소·같은 좌석 재사용·퇴장 페이드와 투명도 복원도 검사했다.
- Unity 렌더링 캡처로 Q/E 안내, 좌석 범례, 책상 위 코스터, 재열린 레시피 창과 등장 페이드를 확인했다. 검증 사본과 실제 프로젝트의 변경된 Assets 파일 55개의 해시가 일치한다. 제조·서빙 전체 완료, 1일차 맥주 실습과 1–3일차 전체 플레이는 별도 확인 대상.

Unity 메뉴 `Tools/Story/Connect Tutorial UI`로 프리팹과 Play 씬의 연결을 다시 적용할 수 있다. 실제 씬 테스트는 `CampaignStoryRuntimeSmokeTests.NewGameShowsIntroNoticeAndCompletesTutorialPreparation`과 `NewGameWithoutTutorialPrefabStillStartsAndPrepares`를 실행한다.

## 제조창 복구와 인물 페이드

- 실제 16:9 화면에서 코스터가 책상 아래로 내려가던 배치를 확인하여 `Tabletop Serve Anchor`를 -2에서 -1.5로 올렸다. 드롭 영역은 낮은 128×58 크기를 유지한다.
- 스토리 제조 가능 상태에도 Tab·메뉴 버튼을 허용한다. 레시피 창을 닫거나 제조 준비의 뒤로 가기로 취소해도 현재 주문과 튜토리얼 전용 레시피 ID는 실행기에 남아 있어 같은 제한으로 다시 열린다. Tab을 놓는 입력은 다시 토글하지 않는다. 제조 준비를 취소한 튜토리얼은 메뉴 재열기 안내로 돌아간다.
- 등장·퇴장에 0.35초 투명도 페이드를 적용한다. `CharacterFade`는 파츠·통짜 초상·랜덤 손님의 원래 RGB 색을 유지한다. 스토리 등장은 카메라가 인물의 자리를 잡은 뒤 시작하며 연속 등장 스텝의 인물은 함께 페이드 인한다. 퇴장은 페이드가 끝난 뒤 인물 리소스를 비우고 카메라 프레임을 바꾼다. 대본 정상 종료 시 남아 있는 인물도 함께 페이드 아웃한다. 영업 손님은 작별 대사가 끝난 뒤 페이드 아웃하고 좌석을 비운다.
- 즉시 정리나 장면 종료에서는 이전 페이드를 취소하고 투명도를 복원하므로 다음 손님이 투명하게 남지 않는다.
