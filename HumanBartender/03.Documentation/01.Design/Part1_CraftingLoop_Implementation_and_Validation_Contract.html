1부 제조 루프 구현·검증 계약

문서 목적

1부 제조 루프를 엔진·JSON·검증 체계에 연결하는 구현 계약이다. 제조 시도와 손님 주문을 분리하고, 서빙 드롭 시 두 데이터를 연결하는 경계를 포함한다. 기믹·판정 내부 공식은 외부 정본에서만 관리한다.

상위 문서: 1부 일반 손님 칵테일 제조 루프 기획서

4. 제조 기믹 시스템 호출

역할: 제조 준비 단계에서 확정한 선택값을 외부 기믹 시스템에 전달하고, 해당 요청의 완료 결과를 한 번만 수신한다.

구분전달·수신 항목이 문서의 책임
입력request_id·selected_cocktail_id·actual_craft같은 제조 시도를 식별하고 실제 선택값을 누락 없이 전달
출력gimmick_results[]·elapsed_manual_sec완료 응답을 해당 request_id에 한 번만 연결
다음 상태기믹 완료 또는 오류완료 시 판정 시스템을 호출하고, 오류 시 결과 확정을 차단

기믹 큐 생성 순서, 개별 조작, UI, 성공·실패 판정, 종료 조건과 내부 오류는 다음 문서를 정본으로 사용한다.

5. 제조 판정 결과 수신

역할: 기믹 실행 결과를 판정 시스템에 전달하고, 결과 화면과 이후 서빙에 필요한 제조 품질값을 수신한다.

반환 항목사용 위치설명
craft_score결과 화면·런타임 기록·QASelected와 Actual만 비교한 0–100 제조 점수
craft_grade제조 결과 화면제조 단계만 반영한 소문자 등급 enum
penalty_breakdown런타임 기록·QA기믹·잔·도구·재료·시간 감점 내역
missing_core_ingredient_ids[]서빙 판정코스터 드롭 시 강제 Sewage 검사에 사용
score_status상태 전이SCORED와 DATA_ERROR 구분

final_grade는 이 단계에서 확정하지 않는다. 코스터에 칵테일을 제공할 때 대상 주문과 Selected를 비교하고 핵심 재료 누락을 함께 검사한 뒤 확정한다.

8. 구현 계약

문서 경계: 1–7장은 플레이 규칙의 정본이다. 8장 이후는 프로그래머가 해당 규칙을 JSON·UI·런타임 상태에 연결하기 위한 구현 계약이며 같은 규칙을 다시 정의하지 않는다.

8.1 시스템 책임

9. 현지화 공통 규칙

  • 모든 사용자 노출 이름·설명·대사는 현재 언어의 ko 또는 en 값을 사용한다.
  • 버튼과 등급 문구는 ui_strings.json을 사용한다.
  • {cocktail} 치환에는 현재 언어의 칵테일 이름을 사용한다.
  • 개발 빌드에서 영어 누락은 한국어 폴백과 오류 로그로 식별한다.
  • 영어 데모 제출 빌드에서는 노출되는 모든 en 값의 존재를 빌드 검증으로 보장한다.
  • UI 레이아웃은 영어 이름·설명과 5–6줄 본문을 기준으로 넘침을 검사한다.

10. 외부 시스템 요청·응답 계약

런타임 인터페이스 정본: 아래 객체는 정적 JSON 파일이 아니다. 한 번의 제조 실행과 결과를 연결하는 런타임 DTO다. actual_craft_ref나 gimmick_result_ref와 실제 객체를 혼용하지 않고, 현재 계약에서는 필요한 객체를 직접 포함한다. 제조 요청에는 guest_id와 order_id를 넣지 않는다.

10.1 제조 세션과 식별자

CraftSessionContext는 제조 화면을 여는 런타임 문맥이다. 주문 표시와 튜토리얼 강제 노출을 관리하지만 공용 제조 채점 요청에는 손님 ID와 주문 ID를 전달하지 않는다.

{
  "craft_session_id": "craft_session_0001",
  "day": 0,
  "mode": "order",
  "ordered_cocktail_id": "gin_tonic",
  "forced_cocktail_id": null,
  "temporary_exposure_cocktail_ids": []
}
식별자생성·수명
craft_session_id제조 화면 진입부터 제공·버리기 또는 세션 취소까지 유지하는 화면 세션 ID
craft_attempt_id한 번의 실제 제조 시도를 식별하는 영속 ID. 제조 결과와 버리기 기록의 소유자
request_idCraftExecutionRequest 한 건의 멱등 토큰. 같은 요청을 재전송할 때 유지하고 새 제조 시도에서는 새로 발급
prepared_result_id채점 완료 후 제공하기를 선택했을 때 생성하는 드래그 가능한 완성 결과물 ID
serve_result_idprepared_result를 유효 코스터에 드롭해 서빙을 확정할 때 생성하는 결과 ID

  • 요청과 응답의 request_id는 반드시 일치해야 한다.
  • 같은 request_id의 완료 응답은 한 번만 수락한다.
  • 기믹 종류에 사용하지 않는 결과 필드는 null로 둔다.
  • score_status = DATA_ERROR이면 craft_score·craft_grade를 null로 두고 error_code에 원인 코드를 기록한다.
  • DATA_ERROR는 플레이어의 제조 실패가 아니라 데이터·Config·참조 오류다. 같은 request_id를 자동 재전송하거나 기본 Target과 0점 결과로 대체하지 않는다.
  • 발생 즉시 제조 입력과 제조 타이머를 정지한다. prepared_result_id·ServeResult·등급·매출·호감도는 생성하거나 반영하지 않으며 오류 런타임 상태는 저장 슬롯에 기록하지 않는다.
  • 오류 팝업은 현재 언어의 ui_data_error_title·ui_data_error_body·ui_data_error_retry·ui_data_error_cancel을 사용해 다시 시도와 제조 취소를 제공한다.
  • 다시 시도는 오류 직전의 동일한 Actual Craft 스냅숏으로 기믹 큐를 다시 생성한다. 같은 CraftAttempt를 유지하되 매 시도마다 새로운 request_id를 발급하고, 이전 오류 응답은 재사용하지 않는다.
  • 제조 취소는 현재 craft_attempt_id를 폐기 상태로 닫는다. 손님의 대기 주문은 유지하고 칵테일 선택 화면으로 복귀한다. 다시 제조하면 새 craft_attempt_id와 request_id를 발급한다.
  • 같은 CraftAttempt에서 같은 error_code가 연속 2회 발생하면 data_error_safe_exit_after_same_code = 2에 따라 ui_data_error_repeat_body·ui_data_error_safe_exit로 안전 이탈을 우선 안내한다. 안전 이탈을 선택하면 오류 상태를 자동 저장하지 않고 타이틀로 돌아가며, 이어하기는 제조 진입 전 마지막 안전 체크포인트를 복원한다.
  • 개발 로그에는 request_id·craft_attempt_id·error_code·same_code_repeat_count를 함께 남긴다. 정상 SCORED 응답의 error_code는 null이다.
  • 정상 SCORED 결과 화면에서 버리기를 선택하면 현재 craft_attempt_id를 폐기 상태로 닫는다. DATA_ERROR 팝업의 제조 취소와 마찬가지로 다음 제조에는 새 craft_attempt_id와 request_id를 발급한다.
  • 채점 완료 후 제공하기를 선택하면 해당 CraftAttempt를 참조하는 prepared_result_id를 생성한다.
  • serve_result_id·target_order_id·final_grade·is_sewage_override·sewage_reason은 유효 코스터 드롭 뒤 ServeResult에서 생성한다.

11. 상태·오류 계약

저장 대상·체크포인트·불러오기·중복 결과 방지는 저장·불러오기 시스템을 단일 기준으로 사용한다. 이 문서는 제조 루프가 발생시키는 상태와 오류만 정의한다.

11.1 주요 상태

손님 큐 생성부터 입장·좌석 예약까지의 PART1_INITIALIZE·SPAWN_WAIT·SPAWN_BLOCKED·GUEST_ENTERING 상태는 1부 일반 손님 운영 런타임 명세을 따른다. 아래 표는 코스터 대기 이후 제조 루프의 상태만 정의한다.

상태화면허용 입력종료 조건
WAIT_COASTER바 내부코스터 드래그, 공용 읽기 패널유효 좌석에 코스터 드롭 또는 인내심 소진
ORDER_DIALOGUE바 내부 대화대사 진행Order Cocktail 저장
SELECT_COCKTAIL레시피 목차·디테일A·D, Space, EscSelected Cocktail 확정
PREPARE_CRAFT잔·도구·재료 선반선택·해제, 레시피 노트, 다음Actual Craft와 제조 요청 생성
PLAY_GIMMICK외부 기믹 시스템 화면현재 기믹 전용 입력완료 응답 수신 후 제조 판정 요청
RESULT완성 연출·결과제공하기 또는 버리기테이블 복귀 또는 재제조
SERVING_READY바 내부완성 잔 드래그대기 주문이 있는 유효 코스터에 드롭·target_order_id 확정
RESOLVING_SERVE수령·음용·반응연출 완료 전 잠금서빙·매출 커밋 완료
GUEST_EXIT퇴장 연출진행 입력좌석 정리 또는 추가 주문 재진입

11.2 오류 처리

오류 코드조건처리
DATA_SCHEMA_MISMATCHbalance.json → config.data_schema_version을 지원하지 않음제조 진입 차단과 현재 버전 로그
COCKTAIL_NOT_FOUNDOrder 또는 Selected ID가 cocktails.json에 없음폴백 칵테일을 만들지 않고 진행 차단
RECIPE_REFERENCE_MISSING확정 레시피의 재료·잔·도구 참조가 없음빌드 차단
CRAFT_DATA_ERROR기믹 실행·제조 판정 중 Target·단위·Config·참조 오류로 score_status = DATA_ERROR 수신결과·서빙·정산 미생성, 오류 자동 저장 금지. 한영 팝업에서 같은 Actual Craft 재시도 또는 제조 취소를 제공하고, 같은 오류 2회 반복 시 타이틀 안전 이탈·제조 진입 전 체크포인트 복원을 우선 안내

SERVE_TARGET_INVALID코스터 없음·대기 주문 없음·이미 소비된 order_id에 드롭잔을 원위치로 되돌리고 상태·반응·매출 변경 없음
DUPLICATE_RESULT_COMMIT같은 attempt·serve·settlement ID를 두 번 확정두 번째 요청 무시와 중복 로그
LOCALIZATION_MISSING현재 언어의 사용자 노출 문자열이 없음개발 빌드 폴백·로그, 제출 빌드 검증 차단

검증 항목통과 기준
