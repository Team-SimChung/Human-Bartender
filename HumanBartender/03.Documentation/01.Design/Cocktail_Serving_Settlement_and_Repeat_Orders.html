칵테일 제공·정산·다회 주문

문서 목적

제조 판정 이후 결과 화면부터 서빙 대상 주문 확정, 반응·매출·다회 주문까지의 흐름을 정의한다. 제조 시도는 손님과 연결하지 않으며, 완성 칵테일을 유효한 코스터에 드롭하는 순간 대상 주문을 확정한다.

상위 문서: 1부 일반 손님 칵테일 제조 루프 기획서

6. 제공·정산·다회 주문

제조 판정이 끝난 칵테일의 결과 선택부터 코스터 서빙, 반응, 정산, 다회 주문, 바 운영 복귀까지 처리한다.

처리 흐름: 결과 연출 → 제공 또는 폐기 → 코스터 드롭 → 주문 대상 확정 → 음용 반응 → 정산 반영 → 추가 주문 또는 퇴장 → 바 운영 연결

결과 연출 중에는 입력을 받지 않으며, 연출이 완전히 끝난 뒤에만 제공하기 / 버리기 버튼을 표시한다.

선택결과
제공하기현재 완성 결과물을 손님에게 전달하는 흐름으로 이동
버리기현재 제조 시도를 폐기하고 공통 칵테일 메뉴로 복귀·모든 대기 주문 유지

이 단계에 들어와도 대기 중인 모든 손님의 Order Cocktail은 바뀌지 않는다.

6.1 결과 연출 완료와 선택 입력

판정 시스템에서 제조 결과가 확정되면 결과 연출 시스템은 Selected Cocktail의 완성 결과물 리소스와 craft_grade를 받아 결과 화면을 완성한다.

플레이어는 결과 연출을 모두 확인한 뒤 제공하기 또는 버리기 중 하나를 선택한다.

6.1.1 결과 연출 진행 순서

외부 기믹·판정 시스템의 완료 응답을 받으면 다음 순서로 결과 화면을 표시한다.

  1. 제조 화면을 페이드아웃하여 암전한다.
  1. 페이드인하면서 손과 완성 결과물을 화면 앞으로 표시한다. 내용물은 Selected Cocktail, 용기는 Actual Glass를 사용한다.
  1. 손과 결과물이 등장하는 도중 확정된 제조 등급 UI가 서서히 밝아지며 나타난다.
  1. 손·결과물·등급 UI의 등장이 모두 끝날 때까지 결과 연출을 유지한다.
  1. 결과 연출이 완전히 끝나면 화면 아래에 제공하기 / 버리기 버튼을 표시한다.

결과 화면의 칵테일 종류와 내용물은 Selected Cocktail을 사용하고, 용기에는 Actual Glass를 반영한다. Actual Ingredients 조합으로 다른 칵테일 ID를 추론하지 않는다.

완성 결과물 구성

내용물 레이어는 Selected Cocktail의 완성 비주얼을 사용하고, 잔 레이어는 Actual Glass 리소스를 사용한다. 두 레이어를 분리 합성해 잘못된 잔 선택도 결과 화면과 서빙 오브젝트에 유지한다.

6.1.2 연출 중 입력 잠금

결과 연출이 시작되면 제조 기믹 입력과 결과 선택 입력을 모두 잠근다.

연출 중에는 화면을 클릭하거나 제조 기믹에 사용했던 키를 입력해도 다음 상태로 넘어가지 않는다.

입력 잠금 중에는 제공하기 / 버리기 버튼을 화면에 표시하지 않으며 보이지 않는 버튼 영역도 입력을 받지 않는다.

등급 연출까지 모두 끝나면 결과 선택 상태를 READY로 전환하고 두 버튼을 동시에 표시·활성화한다.

결과 연출 완료 전에는 선택할 수 없으며, 두 버튼은 연출 완료 후 동시에 활성화한다.

6.1.3 결과 화면 표시 정보

결과 화면에는 플레이어가 이번 제조 결과를 식별하는 데 필요한 정보만 표시한다.

표시 요소기준 데이터표시 내용
완성 결과물Selected Cocktail·Actual Glass선택한 칵테일의 내용물과 실제 선택한 잔을 분리 합성
제조 등급 UI판정 시스템 반환값 craft_gradeui_strings.json → ui_grade_*의 현재 언어 문구
선택 버튼결과 선택 상태제공하기 / 버리기

기믹별 점수·세부 감점은 결과 화면에 표시하지 않는다. 주문 일치 여부를 포함한 final_grade는 실제 서빙이 확정된 뒤 계산하므로 이 화면에서 미리 노출하지 않는다.

6.1.4 제공하기 선택

플레이어가 제공하기를 선택하면 결과 화면을 종료하고 테이블 화면으로 복귀한다.

테이블 위에는 Selected Cocktail의 완성 결과물 리소스를 드래그 가능한 상태로 배치한다.

이 시점에는 아직 제공 대상이 정해지지 않는다. 플레이어가 완성 결과물을 대기 주문이 있는 손님의 코스터 위로 드래그 앤 드롭해야 서빙 대상과 주문이 확정된다.

현재 Selected Cocktail, Actual Craft, 제조 판정 결과는 완성 결과물과 함께 유지하며 코스터 드롭 성공 시 선택된 주문 컨텍스트에 연결한다.

제공하기를 확정한 뒤에는 이전 결과 화면으로 돌아가 버리기로 선택을 변경할 수 없다.

6.1.5 버리기 선택

플레이어가 버리기를 선택하면 현재 완성 결과물을 손님에게 제공하지 않고 폐기한다.

폐기한 뒤에는 모든 대기 주문을 유지한 채 공통 칵테일 메뉴로 돌아간다.

데이터버리기 후 처리
대기 중 Order Cocktail모든 손님·주문 회차의 값을 그대로 유지
현재 Selected Cocktail초기화하여 새 칵테일을 선택할 수 있게 함
현재 Actual Craft폐기한 제조 시도 기록으로 확정·보존
완성 결과물과 등급 UI결과 화면을 종료하면서 제거
잔·도구·재료 선택 상태새 제조 준비를 위해 초기화
전체 제조 타이머다음 제조 기믹 진입 시 새로 시작

버리기는 주문을 취소하거나 실패로 종료하는 선택이 아니다.

플레이어는 공통 메뉴에서 같은 칵테일을 다시 선택하거나 다른 칵테일을 선택해 새 제조 시도를 시작할 수 있다. 새 시도 역시 특정 주문과 연결하지 않는다.

데모 재제조 규칙: 버리기 횟수 제한과 재료비 차감은 두지 않는다. 모든 대기 주문을 유지한 채 새 제조 시도를 시작하며 바 운영 타이머는 계속 정지한다. 버린 시도는 매출·반응·관계값에 반영하지 않는다.

6.1.6 선택 중복 방지

제공하기 또는 버리기 입력이 한 번 확정되면 두 버튼을 즉시 비활성화한다.

빠르게 여러 번 클릭하더라도 제공과 폐기가 동시에 실행되거나 동일한 처리가 두 번 실행되지 않도록 첫 번째 유효 입력만 받는다.

6.2 완성 칵테일 서빙

6.2는 테이블 화면으로 돌아온 플레이어가 완성 칵테일을 손님의 코스터 위에 직접 올려 서빙을 확정하고, 손님이 칵테일을 마신 뒤 반응하는 과정이다.

제공하기 버튼은 테이블 화면으로 돌아가기 위한 선택이며, 실제 서빙 완료 시점은 완성 결과물을 유효한 코스터 위에 드롭한 순간이다.

6.2.1 테이블 화면 복귀

결과 화면에서 제공하기를 누르면 기존 바의 테이블 화면으로 복귀한다.

테이블 위에는 방금 제조한 Selected Cocktail의 완성 결과물 리소스를 배치한다.

완성 결과물은 액체가 채워진 상태이며 플레이어가 마우스로 집어 이동할 수 있다.

손님과 코스터는 제조 진입 전의 좌석 상태를 유지하며, 현재 주문을 한 손님의 Order Cocktail도 그대로 유지한다.

이 상태를 SERVING_READY로 기록하고 유효한 코스터 드롭이 발생할 때까지 서빙 대기 상태를 유지한다.

6.2.2 완성 결과물 드래그

플레이어는 테이블 위의 완성 결과물을 마우스로 드래그하여 손님 앞의 코스터로 이동한다.

드래그를 시작하면 완성 결과물이 포인터를 따라 이동하며, 드롭하는 순간 해당 위치가 유효한 코스터 영역인지 검사한다.

테이블의 빈 공간이나 코스터가 아닌 위치에 드롭하면 서빙으로 인정하지 않는다.

유효하지 않은 위치에 놓은 결과물은 테이블 위의 서빙 대기 위치로 돌아가며 다시 드래그할 수 있다.

드래그 중에는 완성 칵테일의 ID·등급·Actual Craft가 바뀌지 않는다.

6.2.3 유효한 서빙 대상 검사

완성 칵테일을 받을 수 있는 대상은 코스터가 배치되어 있고 아직 제공되지 않은 주문을 보유한 손님이다.

제조 시도에는 손님이나 주문이 연결되어 있지 않으므로, 드롭 순간 코스터의 guest_id·order_id를 조회해 서빙 대상을 확정한다.

드롭 대상처리
코스터 있음·대기 주문 있음유효 드롭·해당 order_id를 target_order_id로 확정
코스터 있으나 대기 주문 없음안착하지 않음·서빙 미확정·원위치 복귀
코스터 없음안착하지 않음·서빙 미확정·원위치 복귀
테이블 빈 공간 또는 코스터 외 영역안착하지 않음·서빙 미확정·원위치 복귀

여러 손님이 동시에 주문 대기 중이면 각 유효 코스터가 서로 다른 target_order_id 후보가 된다. 첫 유효 드롭만 수락하며 제조 시도의 제공 대상은 그 순간 한 번만 확정한다.

6.2.4 코스터 안착과 서빙 확정

완성 결과물을 유효한 코스터에 드롭하면 결과물의 위치를 중앙으로 보정하여 안착시킨다.

안착과 동시에 다음 처리를 한 번만 실행한다.

  • 결과물의 추가 드래그 입력 잠금
  • 드래그 중인 prepared_result_id와 원본 craft_attempt_id를 서빙 입력으로 고정
  • 유효 드롭 한 건에 고유 serve_result_id 생성
  • 코스터의 guest_id·order_id를 served_guest_id·target_order_id로 저장
  • served_cocktail_id = Selected Cocktail.id 저장
  • 대상 주문의 order_cocktail_id와 served_cocktail_id를 비교해 order_match 확정
  • CraftAttempt의 missing_core_ingredient_ids[] 확인
  • 주문이 일치하고 핵심 재료 누락이 없으면 final_grade = craft_grade
  • 주문이 다르거나 핵심 재료가 누락되면 final_grade = sewage로 강제하고 원인을 sewage_reason에 저장
  • 대상 손님의 수령 대사 시작

서빙 판정에서는 Actual Craft를 분석해 다른 칵테일 ID로 바꾸지 않는다. 내용물은 Selected Cocktail, 용기는 Actual Glass를 유지한다.

6.2.5 수령 대사 분기

코스터 안착 직후 손님은 먼저 칵테일을 받은 것에 대한 수령 대사를 출력한다.

수령 대사는 확정된 대상 주문의 order_cocktail_id와 제공된 served_cocktail_id의 일치 여부를 우선 기준으로 선택한다.

주문 일치 여부수령 대사
Order Cocktail = Selected Cocktail올바른 주문 수령 대사
Order Cocktail ≠ Selected Cocktail잘못된·틀린 주문 수령 대사

주문과 다른 칵테일을 제공한 경우에는 일반 감사 대사로 처리하지 않고, 손님이 받은 칵테일이 자신의 주문과 다르다는 것을 인지하는 대사를 사용한다.

수령 대사는 barks.json → voice_id·situation·text.ko·text.en·weight에서 현재 손님의 성격 ID와 상황값에 맞는 행을 추첨한다.

정상 수령은 serve_thanks, 주문 불일치 수령은 wrong_receive 상황을 사용한다.

대사 행의 expression이 비어 있으면 bark_situations.json → [situation].default_expression을 사용한다.

6.2.6 마시는 연출과 빈 잔 교체

수령 대사가 끝난 직후 품질 반응 대사를 바로 출력하지 않는다.

수령 대사와 최종 반응 대사 사이에 손님이 실제로 칵테일을 마시는 연출을 재생할 수 있는 간격을 둔다.

마시는 연출이 시작되면 코스터 위의 액체가 채워진 완성 결과물 리소스를 사용해 음용 상태를 표현한다.

음용이 끝나면 동일한 잔 종류의 빈 잔 리소스로 교체한다.

시점코스터 위 리소스
서빙 직후액체가 채워진 Selected Cocktail 완성 결과물
마시는 연출 중음용 진행 상태의 결과물 연출
마시는 연출 완료완성 결과물과 같은 잔 종류의 빈 잔 리소스

수령 대사 종료부터 마시는 연출 완료까지의 정확한 대기시간과 애니메이션 길이는 연출 데이터에서 관리한다.

6.2.7 음용 후 반응 대사

마시는 연출이 끝나고 빈 잔 리소스로 교체된 뒤 손님의 최종 반응 대사를 출력한다.

반응 대사는 주문 일치 여부와 Final Grade를 기준으로 선택한다.

불일치모든 등급잘못된·틀린 주문 음용 반응을 우선 사용

주문 불일치 시에는 칵테일의 품질이 좋더라도 올바른 주문 품질 대사로 대체하지 않는다.

주문 일치 시에는 barks.json의 react_excellent·react_good·react_decent·react_poor·react_sewage를 최종 등급에 맞춰 사용한다.

주문 불일치 시에는 등급과 관계없이 wrong_drink 상황을 우선 사용한다.

6.3 주문 정산과 후속 분기

6.3은 음용 후 반응이 끝난 주문의 판매금액·팁·배상액을 한 번만 반영한 뒤 추가 주문 또는 퇴장으로 분기하는 단계다.

실행 순서: 최종 반응 종료 → 정산 계산 → 당일 매출 반영 → 추가 주문 조건 검사 → 6.4 재주문 또는 퇴장

추가 주문이 남아 있는 손님은 좌석과 코스터를 유지한 채 6.4 다회 주문 분기로 이동한다.

각 주문의 경제 결과는 내부 당일 매출 누계에 즉시 반영하되 잔별 정산 팝업은 표시하지 않는다.

당일 누계는 2부 end_part 완료 뒤 일일 매출 정산 화면에서 한 번만 표시한다.

주문 결과내부 반영화면 처리
Excellent판매금액 + 성격 배율을 적용한 팁잔별 정산 팝업 없음
Good·Decent·Poor판매금액잔별 정산 팝업 없음
Sewage판매금액 0 - 제공 칵테일 가격 전액 배상잔별 정산 팝업 없음

6.3.1 최종 반응 종료

6.2에서 손님이 칵테일을 모두 마시고 빈 잔 리소스로 교체된 뒤 최종 반응 대사를 출력한다.

최종 반응 대사가 끝나면 해당 주문의 서빙·음용 처리를 종료하고 정산 계산을 시작한다.

현재 주문의 정산을 확정하기 전에는 추가 주문 또는 퇴장 분기로 이동하지 않는다.

정산 계산에는 최소한 다음 결과를 전달한다.

  • Order Cocktail과 제공한 Selected Cocktail의 일치 여부
  • 6.2의 유효 코스터 드롭과 서빙 판정에서 확정한 final_grade
  • 6.2에서 선택한 최종 반응 대사 유형
  • 제공한 칵테일의 판매가격 데이터

대사가 끝나기 전에는 손님을 좌석에서 제거하거나 정산값을 먼저 표시하지 않는다.

6.3.2 판매금액과 팁 계산

판매 기준 가격은 cocktails.json → price에서 가져온다.

등급별 판매율과 팁률은 balance.json → settlement_rules[final_grade]에서 가져온다.

일반 손님의 팁에는 personalities.json → tip_mult를 적용한다.

sale_amount = price × sale_rate
tip_amount = price × tip_rate × personality.tip_mult

현행 규칙에서 Excellent만 판매금액의 20% 팁을 만들며 Good·Decent·Poor는 판매금액만 반영한다.

계산 결과는 현재 주문의 정산 항목에 저장한다. 당일 매출 누계 반영은 6.3.4에서 한 번만 실행한다.

6.3.3 Sewage 배상 계산

Sewage는 balance.json → settlement_rules.sewage의 판매율 0·팁률 0·배상률 1을 사용한다.

refund_amount = price × refund_rate
settlement_amount = sale_amount + tip_amount - refund_amount

현행 규칙에서는 제공한 칵테일 가격 전액이 배상액이므로 해당 주문의 매출 반영값은 음수가 된다.

주문 불일치나 핵심 재료 누락으로 Sewage가 강제된 경우에도 같은 규칙을 적용한다.

6.3.4 매출 누계와 화면 표시

각 주문은 판매금액·팁·배상액을 내부 데이터에서 분리해 저장한다.

주문별 settlement_amount는 당일 매출 누계에 한 번만 반영한다.

1부에서는 잔별 금액·팁·배상 팝업을 표시하지 않는다.

공용 매출 현황 패널은 플레이어가 열었을 때 현재 누계를 읽기 전용으로 보여줄 수 있다.

판매 내역 전체는 2부 종료 뒤 일일 매출 정산 화면에서 한 번만 표시한다.

같은 결과가 재호출되더라도 중복 반영되지 않도록 주문별 고유 settlement_id를 사용한다.

6.3.5 추가 주문·퇴장 분기

현재 회차 정산을 당일 매출 누계에 반영한 뒤 remaining_order_count와 refund_amount를 검사한다.

6.4.1의 추가 주문 조건을 충족하면 손님과 좌석을 유지한 채 6.4로 이동한다. 조건을 충족하지 않거나 남은 주문이 없으면 아래 퇴장 대사 분기를 실행한다.

퇴장 대사는 현재 손님의 voice_id와 직전 음용 반응을 기준으로 barks.json의 bye_good 또는 bye_bad 상황에서 선택한다.

주문 불일치에서는 wrong_receive·wrong_drink 반응을 먼저 재생하며 일반 품질 반응으로 대체하지 않는다.

경제 결과는 퇴장 대사의 긍정·부정 표현이 아니라 balance.json → settlement_rules[final_grade]로 계산한다.

대사 선택과 판매·팁·배상 계산을 하나의 임의 등급 경계로 묶지 않는다.

6.3.6 손님 퇴장과 좌석 정리

정산이 확정되면 손님의 긍정적 또는 부정적 퇴장 대사를 출력하고 퇴장 연출을 진행한다.

퇴장 연출이 끝나면 현재 손님을 좌석과 활성 손님 목록에서 제거한다.

정상 퇴장·코스터 대기 만료·서빙 인내심 만료 등 퇴장 원인과 관계없이, 손님이 사용한 코스터와 코스터 위의 잔을 포함해 해당 좌석에 귀속된 서빙 결과물도 함께 제거한다.

좌석의 주문·서빙·음용 상태를 초기화하고 다음 손님이 사용할 수 있는 빈 좌석 상태로 전환한다.

손님이 화면에서 제거되기 전에 다음 손님 리소스를 같은 좌석에 겹쳐 표시하지 않는다.

유효 코스터 드롭과 서빙 인내심 종료가 같은 프레임이면 balance.json → config.serve_timeout_same_frame_priority = timeout에 따라 퇴장 판정을 우선한다. 이때 드롭은 서빙으로 커밋하지 않고 ServeResult와 정산을 생성하지 않는다. 동시에 드래그 중이던 완성 잔은 서빙 대기 위치로 되돌리고, 퇴장 연출 완료 뒤 코스터와 좌석 귀속 잔을 정리한다.

6.3.7 다음 손님 대기열 전환

현재 손님의 퇴장과 좌석 정리가 끝나면 해당 좌석은 다음 손님을 받을 수 있는 상태가 된다.

대기 중인 손님이 있다면 기존 손님 대기열과 스폰 규칙에 따라 다음 손님을 배치한다.

다음 손님은 코스터가 제공되지 않은 초기 상태로 시작하며, 플레이어가 다시 코스터를 제공해야 주문 단계가 시작된다.

현재 손님의 Order Cocktail, Selected Cocktail, Actual Craft와 서빙 결과는 종료된 주문 기록으로 확정하고 새 손님의 데이터와 섞지 않는다.

6.4 다회 주문과 제조 루프 재진입

일부 손님은 한 잔을 마신 뒤 바로 퇴장하지 않고 같은 좌석에서 다음 칵테일을 주문할 수 있다.

다회 주문 손님은 첫 주문의 음용 후 반응이 끝난 시점에 남은 주문 여부를 확인한다. 다음 주문이 있으면 현재 회차의 정산을 당일 매출에 한 번 반영한 뒤, 손님의 퇴장과 주문 세션 종료만 보류하고 다음 주문 단계로 연결한다.

처리 흐름: 추가 주문 있음 → 2차 주문 대사 → 새 Order Cocktail 확정 → 제조 루프 재진입
종료 흐름: 추가 주문 없음 → 6.3 퇴장 및 최종 정산

6.4.1 추가 주문 여부 확인

6.2의 음용 후 반응 대사가 끝나면 현재 주문의 정산 결과와 예정된 남은 주문을 함께 확인한다.

대사의 표현을 해석해 분기하지 않고, 다음 조건식으로 추가 주문 가능 여부를 결정한다.

can_reorder =
remaining_order_count > 0
AND refund_amount == 0

현재 정산 규칙에서 refund_amount가 0보다 큰 경우는 Sewage다. 따라서 Excellent·Good·Decent·Poor는 남은 주문이 있으면 다음 회차로 갈 수 있고, Sewage는 남은 주문을 취소하고 퇴장 흐름으로 이동한다.

현재 주문 결과남은 주문다음 처리
Sewage 아님있음현재 회차 정산 반영·손님 유지·2차 주문 진행
Sewage 아님없음현재 회차 정산 반영 후 6.3 긍정적 퇴장
Sewage있음 또는 없음현재 회차 정산 반영 후 남은 주문을 취소하고 6.3 부정적 퇴장

첫 번째 주문에서 Sewage가 발생해 손님이 나가면 2차 주문 자체가 생성되지 않는다.

따라서 존재하지 않는 2차 주문의 판매금액·팁·환불액을 계산하거나 최종 정산에 포함하지 않는다.

현재 주문 회차와 실제로 완료한 주문 수를 런타임 상태로 유지한다.

6.4.2 이전 주문 결과 보존

다음 주문으로 넘어가더라도 방금 완료한 주문 결과를 삭제하거나 다음 주문의 Actual Craft에 합치지 않는다.

주문 한 회마다 다음 데이터를 독립된 시도 기록으로 확정한다.

  • 해당 회차의 Order Cocktail
  • Selected Cocktail
  • Actual Craft
  • Final Grade와 Sewage Override 결과
  • 제공·음용·반응 대사 결과
  • 해당 회차의 판매금액·팁 또는 손해액
  • 최종 정산에 더할 부호 포함 회차 정산값

손님 단위의 주문 세션에는 각 회차 기록을 순서대로 연결한다.

각 회차의 경제 결과는 반응 확정 시 고유 settlement_id로 당일 매출에 한 번만 반영한다. 손님 퇴장 시 계산하는 guest_session_total은 로그·검증용 합계이며 당일 매출에 다시 더하지 않는다.

6.4.3 2차 주문 준비

추가 주문이 확정되면 코스터 위의 빈 잔 리소스를 제거하고 다음 칵테일을 제공할 수 있도록 테이블을 정리한다.

손님은 좌석에 그대로 남고 이미 제공된 코스터도 유지한다.

따라서 2차 주문을 받기 위해 같은 손님에게 코스터를 다시 제공하지 않는다.

이전 주문의 Selected Cocktail, Actual Craft, 제조 선택 상태와 결과 화면 상태는 종료된 회차 기록으로 넘기고 새 주문용 런타임 값을 비운다.

손님의 성격 유형과 좌석 ID는 유지한다.

6.4.4 2차 주문 대사

테이블 정리가 끝나면 barks.json에서 현재 손님의 성격에 맞는 reorder 상황 대사를 출력한다.

필드조회 기준
voice_id현재 손님의 personality_id
situationreorder
text.ko·text.en현재 언어의 실제 문장
weight같은 조건의 후보 중 가중 추첨
expression개별 값이 없으면 bark_situations.json → reorder.default_expression 사용

대사 안의 {cocktail}은 새 Order Cocktail의 cocktails.json → name.ko·name.en으로 치환한다.

대사 문장을 구현 코드에 직접 작성하지 않는다.

6.4.5 새 Order Cocktail 확정

2차 주문 대사가 칵테일명을 확정하면 해당 칵테일을 새로운 Order Cocktail로 저장한다.

random_waves.order가 지정된 슬롯은 매 회차 해당 고정 주문을 사용한다. 값이 비어 있으면 당일 해금된 status=confirmed 후보를 매 회차 동일 확률로 독립 추첨하며, 이전과 같은 칵테일도 다시 나올 수 있다. 정본 설정은 balance.json → config.random_order_sampling_mode = uniform_with_replacement다.

이 값은 첫 주문의 Order Cocktail을 덮어쓰지 않고 현재 주문 회차의 Order Cocktail로 별도 저장한다.

데이터2차 주문 시작 시 처리

코스터기존 코스터 유지

2차 주문도 첫 주문과 동일하게 Order Cocktail은 해당 회차가 끝날 때까지 변경하지 않는다.

6.4.6 제조 루프 재진입

2차 Order Cocktail이 확정되면 기존 2번 칵테일 선택 단계로 이동한다.

이후에는 첫 주문과 동일한 시스템을 다시 사용한다.

2차 Order Cocktail 확정
→ 2. 칵테일 선택
→ 3. 제조 준비
→ 4. 제조 기믹
→ 5. 계산 및 등급 확정
→ 6. 제공·서빙·음용 반응

2차 주문이라고 해서 제조 난이도·판정식·제공 방식을 별도로 바꾸지 않는다.

새 제조 기믹에 진입하면 해당 회차의 전체 제조 타이머를 처음부터 시작한다.

6.4.7 다회 주문 매출 반영

각 주문 회차는 음용 반응이 확정되면 고유 settlement_id로 판매금액·팁·배상액을 당일 매출에 한 번만 반영한다.

다음 주문으로 넘어갈 때 이전 회차의 금액을 보류하거나 마지막 퇴장 시 다시 더하지 않는다.

손님 단위 합계는 결과 확인과 로그를 위한 값이며 당일 매출에 재반영하지 않는다.

부정적 결과로 주문 세션이 종료되면 이미 완료된 회차만 유지하고 이후 예정 주문은 생성하지 않는다.

guest_session_total
= sum(order_settlement_items[].settlement_amount)

잔별 정산 팝업은 표시하지 않으며 전체 당일 누계는 2부 종료 뒤 일일 매출 정산에서 한 번만 보여준다.

6.5 바 운영 복귀와 타이머 재개

6.5는 제조 시스템에 들어가면서 일시정지했던 바 운영 상태를 다시 활성화하고, 제공·버리기·다회 주문 결과를 다음 바 운영 흐름에 연결하는 단계다.

바 운영 타이머의 재개 기준은 아래 6.5 규칙을 따른다.

바 화면으로 복귀하면 제조 진입 직전의 남은 시간부터 다시 흐르며, 제조 중 경과시간은 소급 차감하지 않는다.

6.5.1 제공하기 후 바 화면 복귀

결과 화면에서 제공하기를 선택하면 테이블 화면으로 돌아오고 완성 칵테일을 드래그할 수 있는 서빙 대기 상태가 된다.

이 테이블 화면 복귀 시점을 바 운영 복귀로 판단하고 일시정지했던 바 운영 타이머를 다시 진행한다.

복귀 요소처리
코스터 대기 타이머제조 진입 직전 남은 시간부터 재개
서빙 대기 타이머제조 진입 직전 남은 시간부터 재개
신규 손님 스폰 타이머제조 진입 직전 남은 지연시간부터 재개
재촉·최종 재촉·이탈 판정타이머 재개 후 기존 임계치 기준으로 다시 검사

완성 칵테일을 아직 코스터에 올리지 않았더라도 이미 바 화면으로 돌아왔으므로 다른 손님과 스폰 관련 시간은 정상적으로 흐른다.

6.5.2 타이머 값 유지

재개는 타이머 초기화가 아니라 일시정지 해제다.

예를 들어 제조 진입 직전 다른 손님의 코스터 대기시간이 6초 남아 있었다면, 바 화면 복귀 후 다시 6초부터 진행한다.

제조 화면에 머문 시간이 40초였더라도 이 40초를 복귀 순간 한꺼번에 차감하지 않는다.

처리적용 여부
제조 진입 직전 진행값 유지적용
바 복귀 시 초기값으로 재설정미적용
제조 경과시간 소급 차감미적용
정지 중 이벤트 몰아서 실행미적용

6.5.3 서빙 대기 중 바 운영

테이블 위의 완성 칵테일을 코스터로 드래그하는 동안에도 재개된 바 운영 타이머는 계속 흐른다.

플레이어가 제공을 늦추면 현재 손님의 서빙 대기시간뿐 아니라 다른 손님의 대기시간과 신규 손님 스폰 시간도 정상적으로 진행한다.

유효한 코스터에 칵테일을 드롭하여 서빙이 확정되면 해당 주문 손님의 서빙 대기 타이머를 종료한다.

다른 손님들의 타이머와 신규 손님 스폰 타이머는 현재 손님의 수령·음용·반응 연출 중에도 계속 진행한다.

6.5.4 버리기 후 타이머 상태

버리기를 선택하면 테이블 화면이 아니라 공통 칵테일 메뉴로 돌아간다. 대기 중인 모든 주문은 그대로 유지한다.

따라서 아직 바 운영으로 복귀한 것이 아니며 제조 중 일시정지했던 코스터·서빙·스폰 타이머를 재개하지 않는다.

메뉴에서 칵테일을 다시 선택하고 제조를 반복하는 동안에도 타이머는 제조 진입 직전 값으로 유지한다.

이후 새 결과물에서 제공하기를 선택해 테이블 화면으로 돌아올 때 재개한다.

6.5.5 다회 주문 재진입

첫 주문을 제공한 뒤에는 이미 테이블 화면으로 돌아왔으므로 바 운영 타이머가 흐르고 있다.

손님이 2차 주문 대사를 시작하는 동안에도 바 운영 상태는 유지한다.

2차 Order Cocktail이 확정되고 플레이어가 다시 칵테일 선택·제조 시스템에 들어가면 그 시점의 바 운영 타이머를 다시 일시정지한다.

2차 칵테일의 제공하기를 눌러 테이블 화면으로 돌아오면 같은 방식으로 다시 재개한다.

6.5.6 손님 퇴장 후 운영 연결

마지막 주문까지 끝낸 손님의 반응·정산·퇴장 연출이 완료되면 6.3에서 좌석과 손님 상태를 정리한다.

바 운영 타이머는 이미 테이블 복귀 시점부터 진행 중이므로 손님 퇴장 순간 별도로 한 번 더 재개하지 않는다.

정리된 좌석은 다음 손님을 받을 수 있는 상태가 되고, 대기 중인 손님이나 스폰 대상은 기존 규칙에 따라 배치한다.

더 이상 처리할 일반 손님이 없다면 신규 스폰 대신 7번의 1부 종료 조건 검사를 진행한다.

6.7.2 구현 완료 기준

  • 제조 시도에는 guest_id와 order_id가 없고 유효 코스터 드롭 시 target_order_id가 확정된다.
  • 여러 대기 주문 중 플레이어가 선택한 코스터의 주문만 소비된다.
  • 결과 화면과 서빙 오브젝트가 Selected Cocktail 내용물과 Actual Glass 용기를 함께 표시한다.
  • 버리기 후 모든 대기 주문이 유지되고 새 CraftAttempt가 생성된다.
  • 주문별 settlement_id가 당일 매출에 한 번만 반영되며 guest_session_total은 재반영되지 않는다.
  • 결과 연출이 끝나기 전에는 제공·폐기 입력을 받을 수 없고, 연속 입력 시 첫 번째 유효 입력만 처리된다.
  • 유효하지 않은 코스터 드롭은 원위치로 복귀하며 ServeResult와 정산을 생성하지 않는다.
  • 주문 불일치 또는 핵심 재료 누락 시 craft_grade는 보존되고 final_grade = sewage가 확정된다.
  • 현재 회차 정산을 반영한 뒤에만 추가 주문 여부를 검사하며, Sewage 발생 시 남은 주문을 생성하지 않는다.
  • 제공하기 후 테이블 복귀 시 정지 전 타이머 값부터 재개하고, 버리기 후 재제조 중에는 타이머 정지를 유지한다.
  • 유효 드롭과 서빙 인내심 종료가 같은 프레임이면 타임아웃을 우선하고 서빙·정산을 생성하지 않는다.
