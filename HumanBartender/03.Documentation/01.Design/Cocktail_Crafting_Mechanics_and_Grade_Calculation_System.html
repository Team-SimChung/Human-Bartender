프로그래머와 테크니컬 기획자를 위한 칵테일 제조 기믹 실행·제조 등급 계산 공통 명세다. 제조 준비 단계가 만든 실제 실행 큐를 순서대로 처리하고, 플레이어가 실제로 수행한 결과를 craft_score와 craft_grade로 변환한다.

판정 경계: 이 문서는 제조 품질까지만 판정한다. 주문 일치와 핵심 재료 누락에 따른 강제 Sewage, final_grade, 손님 반응과 정산은 완성 칵테일을 코스터에 제공할 때 확정한다.

핵심 원칙

Selected Cocktail은 정답과 채점 기준을 만들고, Actual Craft는 실제 실행 큐의 생성 기준이 된다. 큐 생성은 제조 준비 단계가 담당하며, 현재 문서는 수신한 큐를 재구성하지 않는다. 잘못된 선택을 Selected의 정답값으로 자동 교정하지 않는다.

3. 기믹 큐 실행 공통 규칙

제조 준비 단계가 실제 선택값으로 큐를 만든다. 현재 문서는 수신한 큐를 재구성하지 않고 다음 입력 계약에 따라 검증한 뒤 순서대로 실행한다.

실제 선택실행 큐 처리Target·채점 기준
선반에서 선택한 재료해당 재료의 실제 action으로 Open·Pour·Fill-up 생성Selected recipe와 action·재료 ID 연결
정답 레시피 밖 재료shelf_items.json → prep_action·default_action으로 생성대표 점수에서 제외·추가 재료 감점 후보
셰이커actual_mix = shake·Shake 생성Selected의 정답 도구·mix와 비교
믹싱글라스actual_mix = stir·Stir 생성Selected의 정답 도구·mix와 비교
도구 미선택Shake·Stir 미생성도구 오류와 누락 mix 결과로 판정
auto_apply = trueActual Craft에는 자동 적용·수동 큐에는 미생성데모에서 비채점
  • 올바른 레시피 재료는 cocktails.json → recipe[].action을 사용한다.
  • 정답 레시피 밖 재료는 shelf_items.json의 기본 행동값을 사용한다.
  • 개봉이 필요한 실제 병은 해당 병의 Pour보다 Open을 먼저 실행한다.
  • 같은 action의 재료는 플레이어의 선택 순서를 유지한다.
  • 서로 다른 action은 Open → Pour → Shake 또는 Stir → Fill-up 순서로 정렬한다.
  • 데모의 Squeeze·Powder·얼음은 auto_apply_unscored이므로 수동 큐와 제조 점수에서 제외한다.

6. 제조 점수 계산 흐름

계산 대상

제조 단계에서는 Order Cocktail을 조회하지 않는다. Selected Cocktail과 Actual Craft만 비교해 craft_score와 craft_grade를 계산한다.

  1. Selected Cocktail의 정답 잔·도구·recipe[].scored = true 행과 정답 mix를 Target으로 만든다.
  1. Target action과 Actual 결과를 action·ingredient_id 기준으로 연결한다.
  1. 각 기믹의 개별 점수를 계산한다.
  1. 같은 action 또는 action 계열의 점수를 평균내 대표 점수를 만든다. Fill-up은 Pour 계열에 포함한다.
  1. 현재 채점 대상 기믹 종류의 가중치만 합이 1이 되도록 정규화한다.
  1. (100 - 대표 점수) × 정규화 가중치로 종류별 기믹 감점을 계산한다.
  1. 잔·도구·일반 재료 누락·추가 재료·시간 초과 감점을 더한다.
  1. 100점에서 감점 합을 빼고 0–100으로 제한해 craft_score를 만든다.
  1. grade_cuts의 최소 점수 내림차순 first-match로 craft_grade를 확정한다.

6.1 Target과 Actual 연결

상태조건처리
MATCHEDaction과 재료 ID 일치개별 점수 계산
MISSING_INGREDIENT정답 재료를 선택하지 않아 기믹도 미생성기믹 0점과 중복하지 않고 재료 누락 감점만 적용
MISSING_GIMMICK큐는 생성됐지만 Actual 결과가 없음개별 기믹 0점

DATA_ERRORTarget·단위·Config·참조 오류임의 채점 금지·결과 확정 차단

중복 감점 금지

정답 재료 자체가 빠져 기믹이 생성되지 않은 경우에는 같은 누락을 기믹 0점과 재료 누락 감점으로 동시에 계산하지 않는다.

6.2 서빙 판정으로 넘길 정보

제조 단계는 핵심 재료 누락 여부를 확인해 missing_core_ingredient_ids[]로 보존하지만 강제 Sewage를 적용하지 않는다. 코스터 드롭 뒤 서빙 시스템이 order_match와 핵심 재료 누락을 함께 확인해 final_grade를 확정한다.

7. 기믹별 점수와 대표 점수

7.1 수량형 — Pour·Fill-up

오차율

Error Ratio = ABS(Actual - Target) / Target

오차율개별 점수
0% 이상–5% 미만100
5% 이상–10% 미만90
10% 이상–20% 미만75
20% 이상–35% 미만50
35% 이상0
  • 실제 경계 포함 여부는 balance.json → score_bands[band_type = quantity]를 그대로 읽는다.
  • Target과 Actual은 먼저 같은 단위로 변환한다. unit_oz_to_ml = 30, unit_tsp_to_ml = 5다.
  • Target <= 0 또는 단위 변환 불가는 DATA_ERROR다.

7.2 Open

점수

Open Score = MAX(0, 100 - failure_count × open_penalty_per_failure)

  • 첫 시도 성공은 100점이다.
  • 완료 결과가 없거나 최종 성공하지 못했으면 0점이다.
  • open_penalty_per_failure = 15를 JSON에서 읽는다.

7.3 Shake·Stir

점수

Mix Score = MIN(100, success_count / target_count × 100)

기믹목표 판정 수종료 조건
Shakeshake_target_stacks = 20성공+실패 합 20에서 자동 종료
Stirstir_target_stacks = 10성공+실패 합 10에서 자동 종료
  • 실패는 성공하지 못한 목표 스택으로 이미 반영되므로 실패당 별도 감점을 다시 적용하지 않는다.
  • Shake에는 실패 횟수 기반 조기 종료를 사용하지 않는다.

7.4 대표 점수와 가중치

  • 같은 action의 개별 점수를 평균내 대표 점수를 만든다.
  • Pour와 Fill-up은 하나의 Pour 계열로 합치고 weight_pour를 사용한다.
  • 현재 제조에서 실제 채점하는 종류만 모아 가중치 합이 1이 되도록 정규화한다.
  • 현행 원본 가중치는 open 10·pour 20·squeeze 10·powder 5·shake 20·stir 20이다.
  • 데모에서 자동·비채점인 Squeeze와 Powder는 정규화 대상에서 제외한다.

기믹 감점

Gimmick Error Penalty = Σ((100 - Representative Score) × Normalized Weight)

시간 초과율

Overtime Ratio = MAX(0, elapsed_manual_sec - time_limit_sec) / time_limit_sec

  • 전체 제조시간은 craft_timer_scope = manual_input_active_only를 따른다.
  • 플레이어의 수동 입력이 활성화된 기믹 시간만 elapsed_manual_sec에 합산한다.
  • 성공 연출, 기믹 전환, 결과 연출, 메뉴·준비 화면 대기시간은 포함하지 않는다.
  • Stir의 한 바퀴 2초 같은 기믹 내부 제한시간은 전체 제조시간과 별개다.
  • 시간 초과만으로 강제 Sewage 처리하지 않는다.

9. craft_score·craft_grade와 final_grade

제조 점수

craft_score = CLAMP(100 - Gimmick Error Penalty - Fixed Penalties - Overtime Penalty, 0, 100)

craft_scorecraft_grade 직렬화 값
95 이상excellent
80 이상good
60 이상decent
35 이상poor
0 이상sewage
  • 등급 비교는 반올림 전 내부 정밀도의 craft_score를 사용한다.
  • 내부 enum은 소문자 excellent·good·decent·poor·sewage로 통일한다.
  • 화면 표시명은 ui_strings.json의 현재 언어 문자열을 사용한다.
  • 제조 단계에서는 Order와 Selected를 비교하지 않으며 강제 Sewage를 적용하지 않는다.
  • 코스터 드롭 시 order_match와 핵심 재료 누락을 검사한다. 강제 조건이면 craft_score·craft_grade는 진단용으로 보존하고 final_grade = sewage로 덮어쓴다.

11. 오류와 예외 처리

오류·예외조건처리
DATA_ERRORTarget·단위·변환·필수 Config·참조 오류임의 채점·동일 요청 자동 재시도 금지. craft_score·craft_grade는 null, error_code는 필수. 제조 입력·타이머 정지 후 상위 흐름에 오류 결과 반환
UNSUPPORTED_GIMMICK지원하지 않는 action실행 차단·큐와 참조 문맥 기록
DUPLICATE_COMMIT같은 기믹 완료 이벤트 반복첫 커밋만 유지·이후 이벤트 무시
MISSING_GIMMICK정답 큐는 있으나 Actual 결과 없음정상 플레이 결과로 개별 점수 0점
UNEXPECTED정답에 없는 재료·기믹 결과기록 보존·대표 점수 제외·추가 재료 감점 후보
잘못된 종료 입력자동 종료 기믹의 수동 확정 또는 전환 중 입력입력 소비·현재 상태 유지

폴백 원칙

필수 데이터 오류를 0점이나 기본 Target으로 숨기지 않는다. 정상 플레이 결과인 MISSING_GIMMICK·UNEXPECTED와 구현·데이터 오류인 DATA_ERROR를 분리한다.

12. 확정값과 후속 작업

12.1 현재 확정

  • 실제 선택값으로 실행 큐를 생성한다.
  • 제조 단계에서 craft_score·craft_grade를 확정하고, 서빙 단계에서 final_grade를 확정한다.
  • weighted_representative_v1과 mean_per_action_then_weighted를 사용한다.
  • 실제 채점 종류의 가중치만 정규화한다.
  • 수동 입력이 가능한 시간만 전체 제조시간으로 측정한다.
  • Shake 20스택, Stir 10스택을 사용한다.
  • Shake·Stir 실패당 별도 재감점을 적용하지 않는다.
  • Squeeze·Powder·얼음은 데모에서 자동 적용·비채점한다.
  • 잔·도구·누락·추가 재료·시간 초과 값은 balance.json을 정본으로 사용한다.
  • DATA_ERROR는 플레이 실패와 분리한다. 결과·서빙·정산을 생성하지 않으며, 상위 제조 흐름은 한영 오류 팝업에서 다시 시도와 제조 취소를 제공한다. 다시 시도는 동일한 Actual Craft로 기믹 큐를 재생성하되 새 request_id를 사용하고, 제조 취소는 현재 CraftAttempt를 폐기한 뒤 대기 주문을 유지한 채 칵테일 선택 화면으로 돌아간다. 같은 오류가 연속 2회 반복되면 안전 이탈과 제조 진입 전 마지막 체크포인트 복원을 우선 안내한다.
