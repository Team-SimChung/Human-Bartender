# 외부 화면의 유리 빗물

Unity 6000.3.14f1 / URP 17.3.0의 `OutSide` 메인 카메라에 연결한다. 기존 `FX_Rain`은 공간의 비를 그리며, `WindowRainLayer`는 화면 앞 유리의 물방울을 담당한다. 오디오의 `GameAudioRules.IsRainy`와 별개의 날짜 규칙을 만들지 않고 기존 비 프리팹의 활성 상태·반복 파티클 방출 상태를 읽는다.

## 구성과 렌더 순서

- `WindowRainSimulation`: 가상 픽셀 좌표에서 생성, 표면 장력, 가속도, 마찰, 합체, 작은 잔여 방울과 건조를 계산한다. 실제 3D 물리나 SPH가 아니다.
- `WindowRainMotion`: 카메라의 이동 속도·가속도를 평활화하고 큰 위치 점프를 컷으로 처리한다. 기준 화면 높이는 활성화 시 고정하므로 렌즈 줌만으로 바람이 생기지 않는다.
- `WindowRainLayer`: 위 상태를 관리하고 높이 텍스처·물자국 텍스처와 GPU 입자 버퍼를 갱신한다. 등록한 게임 카메라에만 적용하고 비활성화 시 GPU 타깃·버퍼 및 등록을 해제한다.
- `WindowRainDrops`: GPU 인스턴싱으로 둥근 머리와 늘어진 꼬리, 이동 선분의 물자국을 그린다. 물자국은 시간에 따라 마른다.
- `WindowRainComposite` / `WindowRainFeature`: 최종 장면 색에 굴절, 테두리 음영, 하이라이트, 가장자리의 작은 RGB 분산을 합성한다.

합성 지점은 `AfterRenderingPostProcessing`이다. 현재 설치된 2D 렌더러에서는 Pixel Perfect Stretch Fill 확대와 최종 블릿보다 먼저 실행된다. Screen Space Overlay UI에는 효과를 적용하지 않는다. Capture Camera나 다른 씬·미니게임 카메라에는 레이어를 등록하지 않는다. PPC·후처리가 꺼진 카메라에서도 장면 색을 읽을 수 있도록 중간 색 타깃을 요청한다.

광학 효과는 화면에 이미 그려진 색을 샘플링하는 근사다. 실제 광원 추적이나 물질별 분광 시뮬레이션은 아니다. 밝은 간판·조명의 색은 샘플링된 화면 색으로 굴절된다. 하이라이트 방향은 고정된 연출값이다. Render Graph 경로와 Shader Model 4.5를 사용한다.

## 주요 조절값

`OutSide`의 Main Camera → `WindowRainLayer` 인스펙터에서 조절한다.

| 항목 | 기본값 | 역할 |
| --- | --- | --- |
| `virtualRows` | 270 | 가상 픽셀 격자의 세로 크기. 16:9에서는 480×270 |
| `strength` | 0.45 | 전체 시각 강도(0–1). 0이면 합성 생략, 비의 생성·이동은 계속 계산 |
| `shadingPixelSize` | 1 | 원래 픽셀 크기. 물리 격자 대비 광학 셰이딩 픽셀 크기 |
| `spawnPerSecond` / `maxDrops` | 55 / 650 | 생성 속도와 방울 수 상한 |
| `spawnRadius` | 0.55–1.9 | 대부분의 작은 방울 반지름 |
| `largeDropChance` | 0.03 | 드물게 직접 맺히는 큰 방울 비율. 크기는 흐르기 임계 반지름의 1.15–1.6배 |
| `slideRadius` | 3.2 | 표면 장력을 이기고 흐르기 시작하는 크기 기준 |
| `gravity` / `drag` | 330 / 4 | 하향 가속도와 유리면 마찰 |
| `windFromMotion` / `inertia` | 1.1 / 0.3 | 이동 바람과 가감속 반응 |
| `refraction` / `dispersion` | 0.045 / 0.65 | 굴절과 가장자리 색 분산 |
| `formationTime` / `mergeTime` | 0.4 / 0.38초 | 맺히는 방울의 성장과 합체 후 연결부가 모이는 시간 |
| `stickSlip` | 0.65 | 유리면에 걸려 짧게 감속·정지한 뒤 다시 흐르는 정도. 0이면 비활성 |
| `trailStrength` / `trailLifetime` | 0.7 / 4.5초 | 물자국 진하기와 지수 감쇠 시간(4.5초 뒤 약 37% 남음) |

길이와 속도는 가상 픽셀 기준이다. 계산 좌표는 연속적이며 최종 높이맵과 샘플링을 픽셀 격자에 맞춘다. 종횡비가 달라지면 가로 위치를 비율대로 옮기고 반지름은 유지한다. 카메라 이동에 따른 힘은 중력에 더해지며, 서 있으면 주변 바람을 제외한 이동 반응이 잦아든다.

광학 셰이딩의 픽셀 크기는 기본 1배로 되돌렸다. 16:9에서는 480×270 높이맵과 같은 격자로 광학 효과를 계산한다. 최종 화면의 픽셀 폭은 Pixel Perfect 카메라의 렌더 해상도·확대에도 영향을 받는다. 높이만 선형 보간하고 장면 색은 포인트 샘플링하므로 배경을 흐리는 블러는 추가하지 않는다. 물방울 중앙의 균일한 밝기 가산을 없애고 곡면의 테두리 반사와 반대편의 약한 음영으로 유리의 두께를 표현한다.

강약은 먼저 `Strength`를 조절한다: 은은하게 0.3, 현재 기본 0.45, 뚜렷하게 0.75–1. 전체 광학 결과와 원본 화면의 혼합 비율이며 비의 양은 바꾸지 않는다. 코드에서도 `WindowRainLayer.Strength`로 조절할 수 있다. 픽셀 크기만 바꿀 때는 `Shading Pixel Size`를 사용하고 물리 단위인 `virtualRows`는 그대로 둔다.

작은 방울이 합쳐지거나 큰 비가 직접 닿으면 흐른다. 흐르는 방울 뒤에 남기는 작은 방울은 본체와 겹치지 않도록 배치하고 그 면적만큼 본체를 줄인다. 한 프레임을 여러 물리 서브스텝으로 처리해도 물자국은 전체 프레임의 이동 구간을 잇는다. 비가 그치면 생성 강도가 약 2.5초에 걸쳐 줄고 남은 물기는 흐르거나 증발한다. 일시정지는 `Time.deltaTime`을 따라 멈춘다.

새 방울은 작은 물기에서 약 0.4초 동안 차오른다(방울별 시간 편차). 합체 시 물리 면적은 즉시 보존해 합산하되, 최근 흡수한 방울의 위치·면적 비율을 잠깐 보관한다. 높이 셰이더는 두 덩어리를 매끄러운 거리장으로 연결하고 약 0.38초 동안 연결부가 본체로 모이도록 한다. 빠르게 여러 방울을 흡수할 때는 가장 최근의 연결부 하나를 표현하며 완전한 점성 유체 해석은 아니다. 흐르는 방울의 폭과 꼬리 중심선은 방울별 위상으로 천천히 변하고, 정지 방울의 변형은 작게 유지한다. 형상 시간은 시뮬레이션 시간을 사용해 일시정지하면 함께 멈춘다.

실루엣의 진행축은 가속도 목표 방향인 `heading` 대신 실제 `velocity`를 따른다. 바람이나 좌우 흔들림으로 속도와 힘 방향이 다를 때도 머리와 꼬리가 이동 궤적과 어긋나지 않게 한다. 이동 거리에 따라 유리의 접촉선에 잠깐 붙잡히면 속도를 빠르게 줄이고 약 0.13–0.33초 뒤 다시 중력·바람에 따라 가속한다(기본 강도 기준). 접촉 간격과 정지 시간은 방울별로 다르며, 반지름이 미끄러짐 임계값의 2.2배 이상인 큰 물줄기는 이 짧은 정지를 건너뛴다.

이 짧은 정지는 카메라가 가만히 있을 때만 적용한다. 평활화된 카메라 속도가 화면 높이 기준 초당 0.04를 넘으면 이동 상태로 들어가고, 0.015 아래로 내려오면 정지 상태로 돌아온다. 이동 중에는 기존 정지 시간을 풀고 흐르던 방울의 재부착 기준을 낮춰 연속 흐름을 유지한다. 아직 맺혀 있는 작은 방울은 원래 시작 기준을 유지한다. 카메라 컷은 이동 상태로 처리하지 않는다. 직접 생성되는 큰 방울 비율을 8%에서 3%로 줄이고 흐름 시작 반지름을 2.6에서 3.2로 높여 동시에 흐르는 방울 수를 줄였다.

정지 상태에서도 낮은 부착력(`pin < 1`)의 방울은 계속 흐르고, 높은 부착력의 방울만 짧게 붙잡힌다. 생성 시 정해진 부착력을 재사용하므로 방울의 성향이 프레임마다 무작위로 바뀌지 않는다. 기본 생성 분포에서 약 38%가 낮은 부착력이지만, 실제 화면에서 흐르는 비율은 크기·합체·화면 이탈에 따라 달라진다.

`movementSource`에는 OutSide의 캐릭터 Luna Transform을 연결한다. 카메라와 캐릭터 위치를 각각 평활화해 둘 중 하나가 이동 중이면 연속 흐름으로 처리한다. 따라서 카메라가 화면 끝에 고정된 구간에서도 캐릭터가 걸으면 멈칫함이 해제된다. 이동 기준이 없는 카메라는 기존 카메라 위치만 사용한다. 바람·관성 계산은 기존 카메라 이동을 유지한다.

이동 선분에는 연속적인 얇은 물막을 남긴다. 물막의 두께 차로 약한 굴절과 가장자리 반사를 만들며 별도 타깃에서 서서히 감쇠한다. 합체 중심의 시각 보정은 이전 위치에도 같이 적용해 인위적인 옆 방향 자국을 줄인다.

물방울의 전체 강도 0.45는 유지하면서 물자국만 0.7로 높였다. 물막 굴절과 양쪽 가장자리의 명암 대비도 강화해 배경에 묻히던 이동 경로를 더 잘 읽을 수 있게 한다.

첫 LateUpdate까지 비 파티클 시작을 기다려 초기 실행 순서에 따른 예열 누락을 피한다. 비가 오는 씬에 처음 들어올 때는 예열하며, 건조하게 시작한 뒤 비가 켜지는 경우에는 정상 생성 속도로 젖는다.

## 씬 연결

`Renderer2D.asset`의 WindowRain 피처와 `OutSide.unity`의 Main Camera, `FX_Rain`, 두 셰이더 참조가 저장돼 있다. `Tools/Human Bartender/Window Rain/Connect Outside Scene` 메뉴로 다시 연결할 수 있다. 이미 동일하게 연결된 씬은 재저장하지 않는다. 효과를 끄려면 카메라의 `WindowRainLayer`를 비활성화한다.

## 검증과 비용

`WindowRainTests`를 그래픽 장치가 있는 Unity EditMode에서 `-force-d3d11`로 실행한다. `-nographics`는 사용하지 않는다. 시뮬레이션 검사 외에 Play Mode로 전환해 실제 URP 2D 출력도 검사한다.

- 정지 방울, 하향 흐름, 이동 시 대각선 흐름, 정지 후 안정, 잔여 방울, 비가 그친 뒤 건조.
- 픽셀 스냅 평활화, 카메라 컷, 일시정지, 비활성화·재활성화.
- 최종 출력에서 방울의 좌표와 하강 방향 확인.
- 1920×1080, 1280×720, 1024×768, 줌 및 PPC·후처리 비활성 상태.
- 실제 OutSide 씬의 저장된 비 연결, 카메라별 적용 범위, Overlay UI 분리와 씬 재진입.

캡처는 `%TEMP%/WindowRainValidation`에 저장된다. `outside-wet` / `outside-dry`는 실제 외부 씬에서 시간을 멈춘 뒤 효과를 켜고 끈 비교다. `still` / `walking`은 굴절 대비를 보기 위한 테스트 배경이며 실제 게임 미술은 아니다.

16:9 기본 격자의 두 지속 렌더 타깃은 약 761KiB다(Unity 런타임 메모리 측정). GPU 방울 버퍼와 Render Graph의 임시 색 타깃은 별도이며, 비활성화 시 두 지속 타깃과 버퍼를 해제하고 합성 패스를 넣지 않는다. 테스트의 `performance.txt`는 CPU 시뮬레이션, 방울 제출, 합성 패스 샘플을 기록한다. 방울 제출 시간은 CPU 비용이며 GPU 완료 시간이나 전체 게임 FPS가 아니다. GPU 수치는 합성 패스만 포함하므로 실제 게임 전체의 성능 차이로 해석하지 않는다.

2026-10-20 Windows D3D11 / RTX 3090에서 관련 전체 80개 검사가 통과했다(빗물 12개 포함). 씬 재진입 시 GPU 타깃 생성·파괴 검사도 강화한 뒤 별도로 재실행해 통과했다. 650개 방울의 테스트 측정은 CPU 시뮬레이션 평균 약 0.524ms, 방울 제출 CPU 약 0.046ms, 합성 패스 GPU 단일 샘플 약 0.016ms였다. 배포 빌드·다른 GPU/API의 성능은 측정하지 않았다.

위 80개 실행 결과와 성능 수치는 형태·강도 후속 조정 이전의 결과다. 후속 조정은 사용 중인 게임 에디터를 유지하고 별도 임시 Unity 프로젝트에서 동일 소스·셰이더로 검사했다. 기존 시뮬레이션·카메라 이동 검사 9개와 `WindowRainMorphologyTests` 4개, 총 13개가 D3D11에서 통과했다. 합체 면적 보존·연결부·성장·일시정지, 중간 방울의 정지와 재출발·큰 물줄기의 연속 흐름, 실제 속도 방향을 따르는 GPU 실루엣, 연속 물자국·감쇠, 최종 합성 강도 0/0.45/1을 검사했다. 높이맵과 합성 테스트 이미지는 `%TEMP%/WindowRainOrganicValidation`에 저장한다. 실제 OutSide 전체 씬의 최종 미관·성능 검사는 재실행하지 않았다.

이후 이동 중 연속 흐름·정지 중 혼합 흐름·밀도 감소·물자국 대비를 조정한 최종 검사에서는 19개가 통과했다. 고정 카메라에서도 캐릭터 이동을 감지하는 경로와 작은 방울의 부착 유지도 검사했다. 절대 낙하 거리 회귀 검사는 기존 임계 반지름 2.6을 명시해 물리 동작을 고정 조건에서 확인한다. 새 기본값은 별도 밀도 검사로 확인했다: 동일 시드, 20초 시뮬레이션의 후반 10초 평균에서 이전 생성 설정 대비 흐르는 방울이 정지 시 8.19→3.23개, 이동 시 12.46→3.49개였다. 두 비교군은 모두 최신 혼합 흐름 로직을 사용하며 이 수치는 실제 게임 화면의 개수를 보장하지 않는다.
